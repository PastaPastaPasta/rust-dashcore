# P2b: inbound P2P minimal, implementation notes and D-rows

P2b (PLAN §4.5, SB0 rev6.1) makes the node's inbound side match dashd v24 at M2: the listener,
inbound limits and `AttemptToEvictConnection` over SB6's `inbound` feature, the handshake as
responder, the pre-`version`/pre-`verack` gates, and `getheaders`/`getheaders2` serving (rev1,
F17). Acceptance: M2 exit 2 (inbound transcripts identical to dashd's) and PRD §4.2 behaviours
3–6 for inbound connections. This file records the implementer's decisions where the sources
leave a choice ("decide, record a D-row, continue"). Core line numbers are the release tag
v24.0.0-rc.3's (DEC-82); `np:` is `net_processing.cpp`.

| D3 | Inbound limit: Core's `nMaxInbound = nMaxConnections - m_max_outbound`, with `m_max_outbound = min(8, N) + min(2, N - min(8, N)) + 1` (init.cpp:2608-2613, net.h:1263-1269). SB6 computes `min(8 + 2 + 1, N)`. They agree for `N ≥ 11` (dashd's default is 125). For `N ≤ 10` Core's inbound limit is −1 and SB6's 0, and the outcome is the same: with a limit ≤ 0, both the discouraged test (`nInbound + 1 ≥ nMaxInbound`) and the eviction loop's test (`nInbound − nVerifiedInboundMasternodes ≥ nMaxInbound`) hold for every count, so both evict until no candidate is left and then drop the connection. Kept as is; no change to SB6. | Equivalent outcome; changing SB6's shared formula would buy nothing. The host must still derive `max_outbound_full_relay` as `min(8, N)` and `max_outbound_block_relay` as `min(2, N − full)` for the dial loop (P2a-net / ND1). |

| D10 | `inbound-gates` runs dashd with `-v2transport=0`, and its replay drops `NODE_P2P_V2` from the sim's services and identity. With V2 on (the default), dashd reads an inbound stream whose first 16 bytes are not the V1 `version` header (magic, `version`, padding) as a V2 handshake (`V2Transport::ProcessReceivedMaybeV1Bytes`), answers with its own key, and drops the peer once the "garbage" passes 4095 bytes without a terminator. A capture with V2 on recorded exactly that (debug.log: "start sending v2 handshake", then "V2 transport error: missing garbage terminator"). So with V2 on, no V1 message before `version` reaches the gates; the gates are observable only with `-v2transport=0` (or over V2, which the transcript tool does not speak). SB6's V1 detection already has its tests (`inbound_accept_tests.rs`); every other inbound fixture runs with V2 on and replays through it, since `Sim::accept` then starts each peer in V2 with V1 detection. | Behaviour 6 needs the gates themselves; the V2 key bytes are random, which the transcript format cannot compare. |
