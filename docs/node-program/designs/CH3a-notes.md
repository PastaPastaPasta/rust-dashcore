# CH3a implementation notes

Decisions taken while implementing CH3a (`CH3-chainstate.md` rev2.1). Slice a3's rows are numbered
from D60: the design's D1–D55 and slice a2's own rows come first. Each settles a point the design
leaves open or a shape the landed code forced. Core cites are v24.0.0-rc.3 (`v:N` = `validation.cpp`
line N).

| D56 | **An attempt borrows a facade the hooks do not own** (fix round a2-f1). `EvoHooks` gains `type Facade: Send + Sync` (CH7b's `MembersFacade`; `()` for `NoEvo`), and the opener becomes `begin_attempt<'v>(&mut self, facade: &'v Self::Facade, v: &'v mut VContext, id, origin, target) -> Result<Self::Attempt<'v>, Fatal>`. The connector holds the facade beside the hooks, for example `CoreConnector { hooks: H, facade: Arc<H::Facade>, … }`, and lends it together with V's context. It opens each attempt on a local `Arc` clone: an attempt that borrowed `self.facade` would lock out every `&mut self` method of the connector (E0502), so CH3 §3.2's bracket, which calls `self.connect_inner` while the attempt is open, takes `let facade = Arc::clone(&self.facade)` first. The clone costs one `Arc` refcount per attempt: no state, no heap allocation and no lock. This row supersedes §3.2's `begin_attempt(v, …)` snippet. CH7a's attempt then holds the `AttemptHandle<'v>` that `MembersFacade::begin_attempt(&'v self, &'v mut VContext, id)` returns (the facade and its exclusive `RwLockWriteGuard`, EV addendum §2.6), plus the `&'v` facade it releases through. The hooks stay `&mut` for every hook call and for `finish_attempt`, which applies the whole log and then calls `release_attempt(handle, EffectsApplied)`. **One writer per attempt:** the handle holds the gate from `begin_attempt` until `release_attempt`, and the `&'v mut VContext` borrow makes a second open attempt on V a compile error (E0499; a `compile_fail` doctest on `begin_attempt`). Without that, a second open would wait on the gate V already holds. **Released on every path:** `finish_attempt` runs on every outcome (§3.2), and a handle dropped without it (an unwind) drops the gate after the latch trips (a3's guard; addendum §2.6). `chain/tests/attempt.rs` compiles and runs hooks of CH7a's shape on a real V loop, over a stub facade whose `begin_attempt`, `AttemptHandle` and `release_attempt` have §2.6's signatures. The hooks are driven by a connector of `CoreConnector`'s shape, with the hooks and an `Arc` facade as fields and a `&mut self` bracket. Five hook calls and the log application run inside each attempt with the gate held, and a row write is applied on success and on failure. The gate is released after success, after H11 fails, and on drop. `Facade: Send + Sync` is what makes that connector `Send`. | Sol a2 r1 (Major): with `begin_attempt(&mut self, v: &'v mut VContext)`, hooks that own the facade cannot return a handle that borrows it ("lifetime may not live long enough"). Taking `&'v mut self` instead makes every later hook call and `finish_attempt` E0499. An owned gate (an `Arc` and an owned guard) would change §2.6's signatures. The borrowed facade keeps them exactly, and the facade is process state that external routes take the gate of from other threads, not the hooks' state. |
