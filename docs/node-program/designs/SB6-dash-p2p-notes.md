# SB6: `dash-p2p` implementation notes and D-rows

SB6 has no design of its own (PLAN row SB6: "— (P2a §2.2–2.3 and P2a §3.2–3.9; SB0 §3)"). This file records the implementer's decisions where those sources leave a choice, per the IMPLEMENTER contract ("decide, record a D-row, continue"). Core line numbers are Dash Core v24.0.0-rc.3 (DEC-82), from `/work/scratch/p2a-fable/v24.0.0-rc.3/src`.

| D | Decision | Why |
|---|---|---|
| D1 | `dash-clock` is SB4's crate (`node/sb4-dash-chain` 6611a8ec2), copied byte for byte, so whichever of SB4 and SB6 merges second adds an identical file. | SB0 §2.2 puts `dash-clock` in S. ND1 owns the host services, but SB4 already created the crate. Two independent crates would fork the `Clock` trait the two rows share. |
| D2 | `NetCore::new` takes `events: Arc<dyn NetEvents>` (`wake`, `initialize`, `finalize`) instead of SB0 §3.1's `wake: Arc<dyn Fn()>`, plus the host's `resolver: Arc<dyn Resolver>`. | Core calls `InitializeNode` synchronously before the `m_nodes` insert, and it pushes `version` (P2a §2.2 core M-3, `net.cpp:3648`). Core calls `FinalizeNode` once the peer has left the table. A wake closure cannot carry either. Resolving `-connect`/`-addnode` names and DNS seeds needs the host's resolver (SB0 L5, §7). |
| D3 | Both of Core's receive queues (quorum-priority and normal, with the 100:1 ratio of `PollMessage`) live in `NetCore`, and `pop` is `PollMessage`. It returns `Polled { msg, more }`, not `Option<RawMsg>`. | `fPauseRecv` is computed over both queues together (`net.cpp:4773-4850`), and the reader stops on it, so the queues are net-level. `more` feeds the processor's `fMoreWork`. SB0 §12.1's "P2a-node keeps both receive queues" reads as: the processor keeps the *processing* side (one message per peer per pass). |
| D4 | `RawMsg.payload` is an owned `Vec<u8>`, and `RawMsg` carries `raw_size`. | P2a §2.4 and DEC-51h: the payload is a copy. `raw_size` is the unit of `fPauseRecv` and of `recv_bytes_per_msg`. No `bytes` dependency. |
| D5 | `dial_tick(lp: DialLoop, now, policy)`: one entry point per Core loop (`OpenCon`, `AddCon`, `DnsSeed`), each a resumable state machine returning one `DialPlan` action. | SB0 §3.1 names three steps behind one `dial_tick`. P2a-net runs one OS thread per loop. A resumable step that returns one action (open, sleep, wait for a grant, resolve) keeps every blocking point with the driver. |
| D6 | Handshake functions take a `HandshakeHost` and a `PeerNet` (the Core `Peer` fields that SB6's functions own: their services, starting height, addr relay, ping). They call the host at each point where Core's branch touches processor state (`SetTxRelay` + `sendtxrcncl`, `fPreferredDownload`, misbehaviour, MNAUTH, `qwatch`, time samples). | Core's `version` and `verack` branches interleave net-level and processor-level steps, and the push order (`sendaddrv2`, `sendtxrcncl`, `verack`, `getaddr`, …) is observable. One function in Core's order keeps it right for both processors. |
| D7 | `LocalIdentity` is defined in `dash-p2p` (protocol version, advertised version, user agent, masternode flag). P2a-core's `fingerprint.rs` builds it. | `dash-p2p` cannot depend on `dashd-p2p` (L2), and SB0 passes `LocalIdentity` to SB6's handshake. Services are a `VersionInputs` field, because Core uses `peer->m_our_services`. |
| D8 | The decode-policy table in SB6 holds BS4a's normative columns (gate class, pre-read, read plan, throw outcome, blocks-only and quorum-priority sets) and the exception boundary (`Throw`). The post-read outcome, owner and M2 behaviour columns, and the 74-row *registry*, are P2a-core's. | SB0 §12.1 gives SB6 the "gates and decode policy (§3.2)" and P2a-node the "74-row registry". The normative columns are what both processors read before and at the read. |
| D9 | `NetStore` stores opaque Core-format images by `NetBlob` (`Peers`, `Anchors`, `Bans`). `dash-p2p` does the encoding (`peers.dat` magic and checksum, `anchors.dat`, the ban list). | P2a-net needs `peers.dat`/`anchors.dat` in Core's format through `NetStore`. SPV stores the same bytes in an SQLite table. |
| D10 | `dash-clock` gains `Clock::node_now_micros`, Core's `GetTime<std::chrono::microseconds>()`: a default method only, derived from SB4's `Clock::node_time` (`floor_secs` × 10⁶ + `subsec_nanos` / 1000), which no clock overrides. `SystemClock` therefore keeps its sub-second part, and `MockClock` gives the mock seconds × 10⁶. Rounded down; Core's `duration_cast` truncates toward zero, which differs only before 1970. `node_now_micros_is_node_time_in_micros` pins it under mock time, a fixed sub-second clock, and the system clock (bracketed by two `node_time` reads). | Ping times and `m_time` are microseconds in Core, and mock time is whole seconds. One source of truth (manager ruling at the re-rebase onto SB4): the method has a default, so implementors and `dash-chain`'s `node_time` are unaffected. Until SB4 merged, SB6 carried its own copy with `SystemClock`/`MockClock` overrides; the re-rebase dropped that copy and the overrides. |
| D11 | BIP155 entries are converted from base-sdk's decoded `AddrV2` with Core's `UnserializeV2Stream` post-rules (IPv4 or Tor v2 prefix in IPv6 → invalid `::`, the internal prefix → `NET_INTERNAL`, unknown ids → `::`). The one remaining difference, base-sdk decoding IPv6 `fc00::/8` as CJDNS, is inherited, not re-parsed locally. | That difference is already catalogued in DDE-SWEEP §5 and owned by BS10's base-sdk fix. A second, local addrv2 parser would duplicate the codec. When BS10 lands, the conversion is unchanged. |
| D12 | `NetConfig::priority_queues` (default `true`, Core) selects the two receive queues of D3. With `false`, every message goes to the normal queue and `pop` is plain FIFO. | SPV processes in arrival order and has no quorum-priority traffic worth reordering for. Both modes share one code path; only the queue choice differs. |
| D13 | The ban list persists as Core's `banlist.json` (`{"banned_nets":[{version, ban_created, banned_until, address}]}`, 4-space indent, `CSubNet` order; byte for byte since D53). The reader parses numeric IPv4/IPv6 addresses, `addr/prefix` and `addr/netmask`, and drops other entries the way `BanMapFromJson` drops an unparseable one. | `dash-coreimport`'s faithful `LookupSubNet` is node-only (L4), so layer S cannot use it. Core writes only IPv4/IPv6 subnets for bans it creates from peers. Unifying the two parsers into one S-layer module is a follow-up. |
| D14 | `NetCore` owns Core's `AdjustedTime` (the `timedata.cpp` median filter) and `mapLocalHost`. The handshake records the time sample and `seen_local` itself, so `HandshakeHost` has no time hook (D6 revised). The `HandshakeHost` methods take no `core` argument; the handshake functions take `core` themselves. | Both are `CConnman`/global state in Core, read by the addr and version paths that SB6 owns. Keeping them in the core avoids a host round trip for net-level state. |
| D15 | `NetCore::discourage(peer)` takes no reason, and `ban(net, offset, since_unix_epoch)` uses Core's `BanMan::Ban` arguments. `NetEvents::initialize` receives the core and the peer's `our_services`. | Core's `Discourage` has no reason; the processor logs its own `Misbehaving` line. `Ban`'s arguments are what `setban` passes. `InitializeNode` computes `m_our_services` from the connection type and needs to push through the core. |
| D16 | SPV uses `open()` and the `AddrMan` directly and does not run `DialPolicy` or `dial_tick`. It turns `v1_retry` off (D45). | SPV's peer selection is its own (P2a §2.3); `dial_tick` reproduces Core's `ThreadOpenConnections`, which only the node needs. |
| D17 | D5 revised. The signature is `dial_tick(lp, policy) -> DialPlan`, with no `now`: the core reads its clock. `dial_wait(lp, max)` is the blocking point. Given `None` (`DialPlan::WaitGrant`), it acquires the loop's outbound or manual semaphore itself and holds the `Grant` for the loop's next `Open`. `DialPlan::Resolve { seed, max }` hands a DNS seed to the driver, which calls `resolve_seed(seed, max)` (`x1.<seed>`, at most 32 answers). `DialPolicy` has no `preferred_network`. The core computes `MaybePickPreferredNetwork` from its own per-network counts. | Core's loops read `GetTime`/`NodeClock` inline, so a passed `now` could disagree with the clock that `open()` and AddrMan use. Acquiring a grant is the only part of the loop that blocks on another thread. Keeping it inside `dial_wait` means a driver cannot open without one. The preferred-network choice uses net-level state only (`m_network_conn_counts`, reachable networks with an empty AddrMan table). |
| D18 | Superseded by D36 (SB6 r1 F3): eviction now sorts as libstdc++'s `std::sort` does. | A stable sort picked a different peer than Core whenever keys tied. |
| D19 | The fixed seeds are `convert_seeds(bip155_bytes, now, rng)`, which parses Core's BIP155 table (`chainparamsseeds.h`) from base-sdk's `ChainParams::fixed_seeds`. Entries get NODE_NETWORK and a time drawn from U(now−2 w, now−1 w], as in Core's `ConvertSeeds`. The core's RNG draws the time, so deterministic mode reproduces it. | Core's table is BIP155 bytes and Core draws the time per entry. The test counts the networks (mainnet 170 IPv4 and 25 onion, testnet 19, regtest 0). |
| D20 | `NetSocket` gains `close(&self)`. For TCP it is `shutdown(Both)`; for `MemSocket` it closes both pipes. `DisconnectNodes` and shutdown call it before the reader and writer tasks end. | Core's `CloseSocketDisconnect` closes the descriptor at once, so the remote sees EOF even while a task still holds the `Arc`. Dropping the last reference is too late (the reader may be parked in `select`). |
| D21 | `inbound::accept(sock, addr, addr_bind, permissions, inbound_onion, refuse_unsynced) -> Option<PeerHandle>` is Core's `CreateNodeFromAcceptedSocket` after `accept()`: the whitelist permissions (`-whitelistrelay`, `-whitelistforcerelay`), the network-inactive and banned/discouraged refusals, the inbound limit with `AttemptToEvictConnection`, and `prefer_evict = discouraged`. Three `NetConfig` fields cover the inputs: `whitelist_relay` (default true), `whitelist_force_relay` (default false) and `active_masternode` (default false; it enables the masternode protection in `GetEvictionCandidates`). | The host owns listening sockets (`InitBinds`, P2a-net), so SB6 starts where Core has an accepted socket. Dash's masternode protection reads `m_active_masternode`, which the core needs as configuration. |
| D22 | `diff_addrman` treats the oracle's `DataStream::read(): end of data` as equal to the node's `AutoFile::read: end of file` when a `peers.dat` load fails on a short image. Every other load message is compared exactly. | The oracle loads `peers.dat` from memory (a `CDataStream` under `CHashVerifier`), while `LoadAddrman` reads an `AutoFile`. The node's text is what `LoadAddrman` logs on a real node, so it stays. |
| D23 | `diff_addrman` runs Core's test mode only (`deterministic = true`: `nKey = 1` and a zero-key RNG), with or without Core's test asmap and with `-checkaddrman` 0, 1, 3 or 100. The self-seeding mode (the key and RNG seed drawn from `GetRandBytes`, served from the oracle's draw log) is not compared yet. | Test mode reaches every table operation and every RNG draw after construction; the canonical state includes how far the RNG has run. Self-seeding adds only the two seeding draws, and replaying them needs the draw log fed into the node's RNG construction, a test-only hook that SB6 does not otherwise need. Follow-up: add that hook and a seeded leg. |
| D24 | Withdrawn. `diff_addrman` once treated an oracle operation that Core ran twice as out of domain, because `Oracle::with_buffer` re-ran stateful entries on a buffer retry. O1c fixed that in the shim (Core 9ba8d790f0: a pending output per handle; rdc ffdb8fe5f), so the workaround and its buffer commit are gone. | The manager ruled that a stateful oracle entry runs once per call. |
| D25 | `exponential_rand(now_us, average_secs, u)` reproduces Core's `GetExponentialRand` bit for bit: Core's literal (−0.0000000000000035527136788, not exactly −2⁻⁴⁸), the product in `double` seconds, then the ×10⁶ and the +0.5 µs each rounded to a 64-bit mantissa as x86-64's 80-bit `long double` does (exact `u128` arithmetic). | Plain `f64` differs by 1 µs on a few draws in 400,000 at 24 h averages (the planned `AVG_LOCAL_ADDRESS_BROADCAST_INTERVAL` user). Pinned by vectors from Core's expression compiled with g++; 400,000 random draws at 120 s, 300 s, 1 d and 7 d agree. Platforms whose `long double` is `double` (aarch64 Apple, MSVC) would round like plain `f64`; Core there differs from x86-64 Core, and this follows x86-64. |
| D26 | `deterministic` (a `test-utils` field since the series after fix r1; a build without `test-utils` has no such setting, so no production config can make V2 keys, challenges, nonces or seeds predictable) serves every `GetRandBytes` from the zero-key ChaCha20 stream (`StreamRand::with_key([0; 32])`), so each site takes Core's bytes in Core's way (D38) and runs reproduce; AddrMan keeps Core's own test mode (`nKey = 1`, zero-key context, no stream bytes). The MNAUTH challenge and V2 keys come from that stream in this mode. | The mode exists for reproducible tests of the port; Core's mock mode makes every nonce, tweak and timer equal, which tests nothing useful here. | D27 | Onion, I2P and CJDNS are unreachable unless the host lists them in `NetConfig::reachable_overlays` (default empty), on top of `only_net` (`-onlynet`). As in Core, a non-empty `only_net` also makes the unroutable and internal networks unreachable (`RemoveAll`). | Core removes Onion without an onion proxy, I2P without `-i2psam` and CJDNS without `-cjdnsreachable`, so its default reaches IPv4/IPv6 only. SB6 dials TCP directly and has no proxy path (`ConnectThroughProxy`, `-proxy` name lookups and the `HaveNameProxy` DNS-seed branch are not ported). A host that routes an overlay itself lists it here. The host keeps this consistent with `NetConfig::proxies` (Core couples `SetProxy(NET_ONION)` with Onion reachability, and torcontrol adds it at runtime), and does Core's init check that `-onlynet=onion|i2p|cjdns` has its proxy, `-i2psam` or `-cjdnsreachable`; the core leaves such a network unreachable. Proxy support is a follow-up for P2a-net. |
| D28 | `-blocksonly` reaches the core as `NetConfig::blocks_only`. At shutdown, anchors are the first two peers that are block-relay-only by Dash's `IsBlockRelayOnly`: a block-relay connection, or, with `blocks_only`, any peer without the Relay permission. | Dash's `CNode::IsBlockRelayOnly` (`net.cpp:554`) counts every non-Relay peer under `-blocksonly`, and `GetCurrentBlockRelayOnlyConns` writes those. |
| D29 | The inbound log line is Core's `fLogIPs = false` form without the socket: `connection accepted, peer=N`. | `NetSocket` is an abstraction with no descriptor number, and the core does not take `-logips`: `handshake.rs` writes its `-logips` lines in the `fLogIPs = false` form too. |
| D30 | A failed AddrMan consistency check panics, where Core logs the failure and calls `assert(false)`. The panic message carries Core's text. | D31 | `DialPolicy` callbacks run under the dial lock and must not call back into `NetCore`'s dial API (`add_node`, `add_addr_fetch`, `added_nodes`, …). | D34 | `diff_addrman` compares the RNG's position after every operation (keystream bytes used, the bit buffer), so Core's draw order inside AddrMan is binding. The session targets compare outcomes only; O1c's draw log is a triage aid, not a compared field. | AddrMan's results (`Select`, `GetAddr`, bucket positions, `ResolveCollisions`) are functions of the draw sequence, and the port reproduces it exactly, so comparing the position catches a drift before it changes a result. | D35 | Eviction (inbound `AttemptToEvictConnection`, stale-tip and extra-outbound) and `InactivityCheck` stay out of the session targets on both legs (D32). | D36 | Eviction (`SelectNodeToEvict`, `ProtectEvictionCandidatesByRatio`, through `EraseLastKElements`) sorts with `stdsort::sort_by`, a port of libstdc++'s `std::sort` from GCC 13.3.0, the compiler of Core's release builds (`contrib/guix/manifest.scm:96`). | D37 | DEC-178 splits SB6's 59 payload-reading decode rows three ways (10 + 32 + 17; the other 15 of Core's 74 commands read nothing and are outside the 59), all through `dash-p2p`'s decode boundary (`policy::decode`/`policy::read`). **Oracle-judged** (O2c `oracle_p2p_decode`, Core's own deserializers), 10 rows: `clsig`, `isdlock`, `qsigrec`, `qfcommit`, `mnauth`, `spork`, `platformban`, `qgetdata`, `qdata`, `getqrinfo`. For a `headers2` Core reads, the matrix also builds the headers with its own model of `Uncompress` (version list, splices, derived fields; 1a72a6883) and the model compares the boundary's headers with them. Typed readers for processors (manager rulings after SB6 r2): **`policy::read::<GovSyncRead>`** returns `govsync` with the filter's last three fields typed (`hash_funcs`, `tweak`, `flags`; base-sdk's `GovSync` has none), so no processor reads them by offset; `read::<GovSync>` still reads Core's bytes but keeps no tail. **`policy::read_headers2(payload, ctx, hash)`** is the one lenient `Uncompress` for the processor (P2a-core's `read_headers2` goes, P2a-core D48): a single pass of Core's handler loop calling `hash` exactly where Core's `Uncompress` does (once per header whose previous hash is left off, on the header before it, in order, only for headers read before a failure), so the processor pairs each header with its hash there (P2a's hash-once rule, DEC-51a, P2a-core D17) and a full batch of 8000 costs Core's 8000 X11 (7999 through the hook, the last header's by the processor). The strict and the lenient payload take the same path, so neither hashes twice; a count over `GetHeadersLimit` reads no header and is `ReadError::TooMany { count, max }` (was `Headers2Error`, D51), not a throw (Core's handler scores `Misbehaving(20)` and returns; net_processing.cpp:5323-5327), the count's own throws are `ReadError::Throw`, and a count past the bytes reads and hashes headers until they run out, as Core does (base-sdk refuses such a count up front; same verdict). No state carries across messages: Core's `last_unique_versions` is the message's (PQ-3). It returns the uncompressed headers, which are `decode`'s (`policy::tests::headers2_hash_once_on_both_paths`, and `p2p_decode_model` checks both typed readers against `decode` on every input). `decode`/`read::<Headers2>` keep the strict-first read for the re-encoding the model checks; their fallback re-reads the whole payload after a strict refusal, and a strict refusal can come at any header (a version offset past the list so far, e.g. at header 7999), so `decode` may hash a batch nearly twice; no processor path uses it. `p2p_decode_model` counts the hook's calls exactly on every input, from base-sdk's own parse (`CompressedHeader::is_prev_hash_compressed`), on success and failure alike; that count shares the reader's parser, so it is no oracle of the parser (the matrix's `Uncompress` and SB6 r3's independent Core probe are). Either error leaves the payload as it was (as `policy::read` does, b6a2d1f26): Core's stream has consumed the count and the headers read, and the hook calls already made stay made; both end the message, so no processor reads on. `policy::tests::headers2_hashes_until_the_bytes_run_out` and the model pin it, and `headers2_version_list_holds_seven` (with the matrix's twin) pins the seventh version-list entry and the eighth insertion's eviction at offset 7. Verdicts are judged, not texts. Some throws carry a different text where both sides refuse: `DataStream::ignore()` reported as `read()`; a `LIMITED_*` bound or a count past the bytes reported as end of data through `Throw::from_decode`, though `policy::read` gives the governance bounds Core's text; and addrv2's size texts. A base-message entry in the oracle, so the matrix rows are Core-judged too, is an O2 follow-up and is not built.
