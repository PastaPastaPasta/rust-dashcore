## 4. Notes

- **Gating answers.** Nothing in this packet is behind a V24/evo_shares deployment check. #7858 tests `tx.IsSpecialTxVersion()` and a fixed type list. The three v24-only types (ProviderDissolve, ProUpShare, ProUpSharedRegistrar) cannot reach the mempool before activation, so listing them needs no gate. The only network-dependent row is MN4-01 (`IsTestChain()`, so `params`).
- **#7858 consensus relevance.** It does not change consensus or lock-acceptance rules: received islocks for provider txs are still verified, stored and enforced (ConnectBlock IS-conflict checks and `ResolveBlockConflicts` are unchanged). It changes what rc.4 masternodes *produce*, so on a network of rc.4 MNs, provider txs no longer get locks. Downstream effects all go through existing rules. An unlocked provider tx is mined only after the 10-min age (`IsTxSafeForMining`). ChainLock signing of a block containing one waits for the same age. Children wait for the parent's ChainLock or confirmations. And no IS-conflict block invalidation can be triggered *by* a provider tx's lock, since none exist. For the evo/consensus auditor: provider txs are still evicted for non-input conflicts (collateral, keys, service address, proTxHash; see #7846/#7857 in the evo packet). Each such eviction is a `TransactionRemovedFromMempool(CONFLICT)` and, with #7839 (MN4-07), now releases IS tracking.
- **MN4-08 hand-off (consensus auditor).** Classed CON; rdashd must reproduce rc.4's index semantics exactly.
- **MN4-05 hand-off (governance/consensus).** The rate state decides which triggers a node holds. Superblock payment validation uses the node's best trigger. Only a masternode that keeps submitting failing triggers is affected, and an honest network's triggers come from other MNs too, but GV1b must model `mapLastMasternodeObject` exactly, including persistence across restart (it is in governance.dat).
- **MN4-01/02 interop.** The node is v24-only, but rc.3/rc.2-era peers on testnet still exist. rc.4 keeps answering GETSPORKS, so older peers are unaffected. rdashd must keep the GETSPORKS handler (with its v24 repeat dedup, dashd-masternode/src/sporks/handler.rs:64-76) and stop *sending* it.
- **CoinJoin (#7537) scope.** Most of the PR closes cross-thread windows. rdashd's CJ0 is a single-owner state machine (`tick` plus message handlers, effects list), so those windows don't exist there. Only MN4-11/12/13 change outcomes in serial order. For fidelity, CJ0 should also adopt the rc.4 effect order on the timeout-finalize path (DSFINALTX relay first, then ConsumeCollateral) and the rc.4 `charge_fees` placement (after the eligibility recheck). Both are free to match.
