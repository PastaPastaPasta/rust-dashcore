## 4. Notes

**Persisted formats.** No wallet record format changes; seed derivation (`CMnemonic::ToSeed`) and the stored hdchain
mnemonic/passphrase encoding are unchanged. Persisted *content* differs in these cases:
- WAL4-13: wallets produced by `migratewallet` drop nonstandard PURPOSE strings.
- WAL4-16: `lockedutxo` / `cj_pending_obs` records are re-persisted after a fault.
- WAL4-01: an over-cap legacy `upgradetohd` no longer bumps the `minversion` record. rc.3 called `SetMinVersion(FEATURE_HD)` before throwing.
- WAL4-02: an over-cap `createwallet` no longer creates a database directory. rc.3 legacy threw after `MakeWalletDatabase`.
- WAL4-08: a failed `restorewallet` never deletes a pre-existing directory.

The `-allow-deprecated-long-mnemonics` path stores passphrases of 249–256 bytes in the hdchain/descriptor mnemonic record. That is the same format, and rc.3 could already store them.

**Surprises.**
- release-notes-27217 says unrecognised purposes give "loading warnings". Dash's port only calls `WalletLogPrintf` (walletdb.cpp:411), so `loadwallet`/`createwallet` `warnings` are unchanged. Not an RPC delta.
- WAL4-02's check sits before the duplicate-name check and also fires for `-usehd=0` legacy wallets.
- The arg is consumed only by a successful first-run creation, so one over-cap `-mnemonicpassphrase` makes every later non-blank `createwallet` fail until restart.
- #7827 also changes the raw-signing scriptSig for the refused input. rc.3 left the supplied scriptSig untouched; rc.4 rebuilds it through `ProduceSignature`. The functional test pins this only for P2PKH (empty).
- `analyzepsbt`'s `Input %u specifies invalid prevout` branch (src/node/psbt.cpp:46) can't be reached for out-of-range indices now. The decoder rejects them first.

**rust-dashcore matches rc.3 in two places.**
- key-wallet's passphrase limits and error text (WAL4-01/02), with the WL1 regtest differential asserting rc.3 dashd behaviour (wallet_mnemonic_differential.rs:57,260-265).
- dash-args and dash-rpc-spec generated tables (WAL4-03, WAL4-09 help).

Everything else lands in not-yet-written dashd-wallet (WL2a/WL2b/WL3/WL4/WL6).

**Cross-area hand-offs.**
- RPC packet: the PSBT RPCs in src/rpc/rawtransaction.cpp (`decodepsbt`, `combinepsbt`, `finalizepsbt`, `utxoupdatepsbt`, `joinpsbts`, `analyzepsbt` via src/node/psbt.cpp) inherit WAL4-15's decoder error. Also regenerate dash-rpc-spec at rc.4 (importelectrumwallet help).
- p2p-init/util packet (or whoever owns dash-args): add `-allow-deprecated-long-mnemonics` (WAL4-03) to the arg/help tables, including the hidden registration for no-wallet builds (dummywallet.cpp:64).
- CoinJoin/MN packet: WAL4-16 is client-side wallet persistence only. No CoinJoin P2P message or server behaviour changes.
