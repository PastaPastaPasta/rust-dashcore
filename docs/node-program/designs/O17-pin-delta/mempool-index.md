## 4. Notes

**Surprises**
1. In **v23 the mempool admits already-mined and duplicate-index asset unlocks** (version 1): mempool `CheckSpecialTx` passes `indexes=nullopt`. They linger until the expiry height, and the miner silently drops them through credit-pool failure. v24 rejects them, holds one claimant per index and evicts conflicts on block. The difference is ungated and visible to Platform on mainnet today (MPIX-15).
2. `MANDATORY_SCRIPT_VERIFY_FLAGS` growth (MPIX-01) turns four unscored "non-mandatory" rejects into +100 bans. It also changes block reject reasons in the single-threaded script-check path, which CS6's "Core's result per mode" table must carry per profile.
3. **Index migration is destructive** (MPIX-08). A v24-run datadir moved back to v23 with an index still enabled and its legacy flag true starts *without error* on an empty legacy index. CH6/IM and RL2 must detect this, for example via `indexes/{addressindex,spentindex,timestampindex}` existing next to a `blocks/index` that lacks `a/u/p/s` rows.
4. #7744 (MPIX-16): v23.1.8 punishes, with +100, honest peers that relay an AU valid at their own height but outside ours. This is a probe-visible fingerprint, not an interop break.
5. #7754 (MPIX-06): a v23.1.8 mainnet masternode config with `-peerblockfilters=0`, `-maxuploadtarget`, raised `-minrelaytxfee`, or reduced `-maxmempool`/`-mempoolexpiry` is refused by v24.
