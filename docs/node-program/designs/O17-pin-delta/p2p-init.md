## 4. Notes

**Surprises**
1. **One message tells the pins apart on mainnet (P2P-04).** v24 treats inv type 34 as a known `tx`-class type from any peer, on any network: it requests it, serves it and enforces it as a blocks-only violation. Only the announcement is version-gated. A v23 profile must make type 34 unknown end to end, not only stop announcing it.
2. **v23's object downloader is global-stateful (P2P-07).** Any received copy of a hash, valid or not, stamps `g_erased_object_requests`, and every later announcement of that hash from any peer is skipped until the 50k–100k limitedmap evicts it. Under v24 an object rejected from one peer is fetched again from the next one. Of all the downloader differences this one is the easiest to probe, and it changes which txs a v23 node ever re-fetches after a tip change.
3. **Configs that are valid on v23.1.8 fail to start on v24** (P2P-24, P2P-33, P2P-34, P2P-35, P2P-36, P2P-37), for example:
   - `bind=<ip>` with default `listenonion`
   - an occupied P2P port
   - a stale `debug=` category
   - `txindex=0` with governance on
   - an unused datadir `dash.conf`

   On mainnet rdashd must keep v23's tolerance, or MN operators migrating from v23.1.8 hit hard failures.
4. **#7808 changes mainnet-visible governance sync** (P2P-19: one peer per object → three). This came in through the rc.3 backport merge, so the evo auditor may not see it as P2P.
5. **No delta where one was expected.**
   - Compact-block short IDs: the instance hash equals the v23 txid.
   - Locators are identical.
   - #7398, #7348, #7347, #7438, #7293, #7332 and bitcoin#27608 are all in v23.1.8.
   - The handshake is byte-identical apart from version, UA and service-bit overrides (P2P-35: v24 refuses an explicit `peerblockfilters=0` on an MN).

**ReleaseProfile shape**
- **`p2p.object_download: enum { Legacy, TxRequest }`.** This is the right granularity. P2P-05..P2P-09 and P2P-11, plus the NOTFOUND fallback in P2P-10, are all consequences of which scheduler runs. Splitting them into separate booleans would allow combinations that neither pin has.
- **Keep `p2p.notfound_limit` separate.** It can be set independently.
- **No field for the send-side version gates.** Keep `protocol_version` as the single source of truth: every ≥ 70241 send-side gate follows from it automatically (P2P-03). `p2p.msg_asset_unlock` is still needed, because the receive side has no gate.
- **Add an `init.*` group** for startup and config tolerance: P2P-24, P2P-25 (init half), P2P-29, P2P-33, P2P-34, P2P-36, P2P-37, P2P-38. Separately, `mn_init` covers P2P-35.
- **Add a `governance.*` group** (P2P-19, P2P-21).
- **One clock switch, `clock.adjusted_time_for_sync`,** shared by A1#4 and P2P-16.
- **Behavioural RPC differences** that the generated `RpcSurface` (names, args, help) cannot express need small `rpc.*` flags: P2P-25 (RPC half), P2P-26, P2P-27, P2P-28 (`hex`), P2P-32.
