### 4. Notes

**A1 row 24 and the integrator's three points.**
- (a) **Confirmed.** The v24 pre-pass (blockprocessor.cpp:259-264) runs after `GetCommitmentsFromBlock` (`bad-qc-payload`, `bad-qc-commitment-type`, non-rotated `bad-qc-dup`, `bad-qc-premature` keep precedence) and after the count checks (`bad-qc-not-allowed`, `bad-qc-missing`), but before BLS (`bad-qc-invalid`) and before every `ProcessCommitment` error.
- (b) **Confirmed.** v23 blockprocessor.cpp:370-375 erases `minableCommitmentsByQuorum`, `minableCommitments` and the has-mined cache for the first copy. These erasures are not undone when the second copy fails and the EvoDB transaction is dropped. Afterwards `GetMineableCommitments` (v23 :741-790, null fallback :775-779) builds a null commitment for that index, and `AlreadyHave(MSG_QUORUM_FINAL_COMMITMENT)` turns false, so the node re-requests the commitment only if it is announced again. v24 rejects before any `ProcessCommitment`, so nothing is erased. The same erase-then-fail pattern still exists on both pins whenever an earlier commitment passes and a later one fails for another reason; only the duplicate case differs.
- (c) **Partly refuted.** The code reading is right: v24 accepts a byte-identical stored (qc, blockHash) and calls `AbortNode` on a `WriteDerived` mismatch. Neither path is reachable in single-chainstate operation at rc.3:
  - A stored value that differs is rejected `bad-qc-dup` by the `SerializedEqual` branch (:381-392) before `WriteDerived` (:432) is reached, the same string as v23. `WriteDerived`'s mismatch arm needs a cross-chainstate read inconsistency.
  - A byte-identical stored value at connect time needs a block reconnected while its commitment is still in EvoDB. `UndoBlock` erases it unless another chainstate contains the block. `ReplayBlocks` requires the EvoDB best block to equal the old coins tip (v23 validation.cpp:4910-4912, evo flushed after coins at :2885-2891), so a rolled-forward block never finds its own commitment.
  - Both paths therefore need a snapshot chainstate, which rc.3 cannot create in production. No profile row; evo already lists #7456 as internal.

**A1 row 21 (DKG part).** Confirmed: v23 only soft-sets `-peerblockfilters=1` and `-blockfilterindex=basic` (v23 init.cpp:1046-1057) and accepts `-blocksonly=1` and an explicit `-peerblockfilters=0`. v24 InitErrors both (init.cpp:1414-1419, #7754 = mempool-index MPIX-06).
