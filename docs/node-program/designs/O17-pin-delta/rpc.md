### 4.4 ReleaseProfile shape
`ReleaseProfile.rpc` should be a generated `&'static RpcSurface` per pin (AR2). It holds the method table, args and conversion table (RPC-13), result docs, the error-string table (RPC-26/32/42/43/49), REST endpoints, help, and the set of `-deprecatedrpc` names each pin honours (v23: `fees`, `banscore`, `legacy_mn`, `exclude_coinbase`; v24: `softforks`, `service`, `permissive_bool`, `banscore`, `legacy_mn`, `walletwarningfield`). Next to it, a small `RpcBehaviour` struct of code-path switches that data alone cannot express:

- `arg_check: Lazy | Declared` (RPC-11)
- `composite_args: Permissive | Strict` (RPC-12)
- `doccheck: TopLevel | Deep` (RPC-15)
- `rawmempool_order: DepthAndScore | Hashed` (RPC-22)
- `verifychain_strict` (RPC-34)
- `index_errors: V23 | V24Async` (RPC-35)
- `dkgstatus_next_block` (RPC-36)
- `listdiff_legacy_evo_addresses` (RPC-41)
- `deployment_json: NextBlock | AtBlock` (RPC-03)

Batch whitelisting, REST URI checks, the HTTP shutdown wait, the REST getutxos lock and list-prepared clamping should be v24-all.

### 4.5 DIFF-RPC (O14)
- Run each pin with the same `-deprecatedrpc` set. With `service` enabled on both, the RPC-40 differences disappear and the comparison can concentrate on real ones.

### 4.6 Ambiguities
- RPC-14 (CLI display) and RPC-22 (array order) are classified `profile` under the "observable" rule. O14 may prefer to treat them as ALLOWED-DIFFS.
- The `quorum sign`/`platformsign` snapshot refusal ("Quorum signing is disabled until snapshot background validation completes") and the `masternode status` suffix depend on an unvalidated snapshot chainstate. Neither pin can activate one through RPC (`loadtxoutset` is absent), so I treated them as unreachable; `quorumParticipation` (RPC-44) is still always emitted.
