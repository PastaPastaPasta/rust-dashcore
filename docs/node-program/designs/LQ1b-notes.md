# LQ1b: DIP0024 rotation: implementation notes and D-rows

LQ1b implements the rotated half of LQ1's design (`LQ1-quorum-members.md` §3.6, §6.3–§6.4, §9): quarters, skip lists and skip modes, snapshot rows as effects, the first V20 cycle, `UsedSet` in `dash-dml`, and the rotated `members_uncached`, made `pub`. This file records the implementer's decisions where the design leaves a choice, per the IMPLEMENTER contract. Row numbers continue LQ1a's (D1–D14, in LQ1a's report). Code comments cite rows as "LQ1b D*n*".

What LQ1b adds:
- `dash-dml::views::UsedSet`: the rotation's scratch list. It follows Core's `AddMN` order: proTxHash, internal id, then unique properties all-or-nothing.
- `dash-evo::llmq::rotation`: Core's quarter rotation, without its store (`ComputeQuorumMembersByQuarterRotation`, `BuildNewQuorumQuarterMembers`, `GetQuorumQuarterMembersBySnapshot`, `BuildQuorumSnapshot`), the skip-list codec and `skip_removed_mns`.
- `node-l1`: the rotated L1 differential, the fuzz target `diff_quorum_members_rot`, and the history replay and captures (`tests/l1_llmq_history.rs`).
- `dash-oracle-sys/scripts/collect-llmq-rotation.py` and `gen-llmq-rotation-captures.py`.
- `test-vectors/lq1-rot/`: 12 rotated captures, described in its `PROVENANCE.md`.

| D | Decision | Why |
|---|---|---|
| D15 | `members_uncached` takes no effect sink. The `SnapshotRows` implementation it is given records the row store as an effect: the attempt overlay inside a validation attempt, the runtime rows otherwise. | One write path for rows (EV addendum §2.6). A sink argument would duplicate what the rows interface already sees, and could disagree with it. |
| D16 | A rotated type with `size < 0` (or more than 65,536 quorums) is `ParamsOutOfDomain` when `LlmqCtx` is built (`ctx.rs`). | Core computes the quarter size from `size / 4` and sizes vectors from the quorum count. A negative or huge value is undefined there, so the context refuses it instead of reproducing it. |
| D17 | A work block below genesis (`cycle_base − 8 < 0`) is `MemberError::Missing(cycle_base)`. Tests seed no rows below cycle 8. | Core dereferences a null `pWorkBlockIndex` there, and the design maps such reads to `Missing` (LQ1a D5). |
| D18 | In mode 0 and mode 1, a snapshot bit past the end of the row's bitset counts as unused. | Core reads past its vector (undefined behaviour). Rows Core writes always cover the list, so only a corrupt or seeded row can be shorter. Seeded rows in tests are at least as long as the eligible list. |
| D19 | Precompute skips the genesis block. | Core's precompute needs `pprev`, which genesis lacks. No rotated type is enabled at height 0. |
| D20 | The design asks for effect emission in the failed and proposal paths checked at node level through `diff_chain` (O2b). `diff_chain` does not exist yet. The model-level cases are done: EV addendum §2.6 cases 1–6, including case 4 (failed and check-only attempts still apply their rows). The node-level check is a follow-up for when O2b lands. | No other node-level driver exercises those paths. |
| D21 | Per-cycle `quorum rotationinfo` is replaced by per-cycle byte equality of the stored row against the oracle shim over the full pure-read replay, plus a rows digest per network (`rows_digest`, recorded in PROVENANCE). | `quorum rotationinfo` is not a pure read, so the live oracles forbid it (LQ1 §6.3.6). The shim gives the row Core stores (`StoreSnapshotForBlock`) for every cycle, which is what `rotationinfo` would report. |
| D22 | The capture set is one LLMQ_60_75 cycle per era (LQ1 §6.3.2 item 4) and network, plus testnet 838,368. Mainnet: 1,737,792; 1,738,656; 1,899,072; 1,987,776; 1,988,064; 2,089,728. Testnet: 769,824; 850,176; 905,184; 1,067,040; 1,572,480. Testnet 838,368 has 7 valid masternodes at its work block, fewer than a quarter (15), so Core returns early (28e) and stores no row. | These are the eras the design lists, within the mainnet oracle bound (2,090,000). 838,368 is the only real 28e cycle in either network's history, so it is kept as a vector. |
| D23 | Harness lists use one internal id per proTxHash for the whole collection (`ids.json`), not `dml-listdiff-check.py`'s positional ids. | Rotation mixes entries of several lists into one scratch list, and Core's `AddMN` refuses a duplicate internal id (an exception it swallows, 28b). With positional ids, masternodes silently dropped out, and almost every mined commitment failed its membersSig check. The regtest generator (`gen-llmq-regtest.py`) has the same latent issue but nothing is removed there yet: follow-up. |
| D24 | Collector residual risk: a list built from diffs is kept once the next full read confirms the latest list, so an error that appears and then disappears between two full reads (at most 8 cycles) would go unseen. Full reads are forced at the first cycle, every 8th cycle, the last cycle, the four work blocks of every capture and every new operator key. | Every mined commitment (125,130: 38,598 mainnet, 86,532 testnet) verifies with Core's members computed from those lists, signatures included. That is an end-to-end check that a wrong list would fail. |
| D25 | Captures embed the members and rows Core computed, and `rotated_captures_match_core` re-derives them with Core and the model. Each list head carries the collection's id count where evodb has `nTotalRegisteredCount`. | Shared vectors (SB11, SB15) need the expected values without running Core. The rotation never reads the registered count. |
| D26 | `SnapshotRows::get` returns `Ok(None)` for a stored row that does not decode. This binds CH7b's row store, which persists rows as bytes. | Core's `CDBWrapper::Read` catches the deserialization error and reports the row absent, so the rotation stops at it instead of failing. |
| D27 | A cycle's row is optional end to end: the model, the history replay, the captures and the generator all handle a cycle where Core stores none. | 28e occurs in real history (testnet 838,368, D22). |
| D28 | Core's `skipRemovedMNs` is a separate function, `skip_removed_mns(chain, cycle_base_height)`, with a unit test on the real mainnet, testnet and regtest parameters. | A mutation that removed the testnet clause survived the captures. Only the full testnet replay caught it (at 794,880). |
| D29 | Fuzz acceptance (DEC-184, DEC-186): night `lq1b-rot` (10-15) is neither a plateau nor a certification. node-bench interrupted 39 of its 46 slices: 12.2 CPU-h used, 3.3 credited. `fuzzctl triage --recheck` closed one stale open cluster on the rotation leg; its vector no longer reproduces. Night `lq1b-rot2` ran `diff_quorum_members_rot` and `diff_quorum_members` (LQ1b changes the facade the latter drives) after node-bench was idle. Both certify windows reported `status=growing`, so night `lq1b-rot3` followed. Each leg is certified with `fuzzctl certify` once it plateaus. Every run so far: 0 divergences, 0 crashes. `diff_scan_quorums` and `diff_select_quorum` are left to the manager. | Per-leg coverage lives in the private tree, which implementers do not read, so fuzzctl's verdicts are the evidence. LQ1b does not change what the scan and select legs exercise. |
| D30 | The predictor returns `Ok(None)` for a type the chain does not configure, and otherwise predicts without storing a row. | Nothing to predict for a type that is not configured. The predictor answers it as "no members" rather than as an error, and never stores a row. |
| D31 | The interim `RotatedCycle`, `no_rotation` and `NoRows` APIs were removed. The rotation is reached only through `members_uncached` and the facade. | They duplicated the facade's entry and let callers bypass the rows interface (D15). |
| D32 | The reference model reports a stored row as `ModelEvent::Row`, which L1 compares with the shim's `TraceEvent::Row`. | That makes row storage part of the trace equality, so a missing or extra store fails the differential. |
| D33 | `QuorumPrecompute` stays as the interface the precompute entry is called through. | CH7b owns the production precompute and implements it. |
| D34 | `SkipListEncoder` is public. | SB11 (dash-mnlist) and the fuzz target build skip lists the way Core does. |
| D35 | The reference model's rows persist across a simulated restart. | Core's rows are in evodb, and a restart must not change members. |
| D36 | Some code-simplifier suggestions were declined: the four parallel window `retain` calls, the 8-argument `check_cycle`, and the `eras` list in the captures test. | Each would add a struct or lose debug output for little gain. |
| D37 | Fuzz acceptance closes under DEC-184. The rotation leg's reopened cluster was triaged by the designated reader (10-16) as a harness artifact, not a divergence: a slice stop can leave an empty timeout file that replays clean. `fuzzctl triage --recheck` closed it, and certify ends its window by stop file instead. The harness fix is a separate node-fuzz task. Certify on 10-16 gave `status=growing` for both `diff_quorum_members_rot` (13:52Z) and `diff_quorum_members` (12:51Z), after nights `lq1b-rot` (12.2 CPU-h, 3.3 credited), `lq1b-rot2` (11.6, 1.5) and `lq1b-rot3` (16.0, 2.2; 12 of 19 slices interrupted by node-bench), plus four certify windows. Every run had 0 divergences and 0 crashes, and the rotated history is Core-exact on both networks (D21–D24). The 72 CPU-h plateau is deferred to the train-14 nightly lane, and no further LQ1b night runs. | Manager ruling 10-16 under DEC-184: a leg that still grows needs farm time, not another task night, and the equivalence evidence does not depend on it. The per-leg growth curves live in the private tree. |
| D38 | Train 14 (with O2a-SP's oracle, ABI 17): `seed_mined` seeds a rotated commitment by having both sides do what a node does before mining one. Before the first rotated commitment, Core and the model's `ModelMembersFacade` connect every block to the tip, once (`PreComputeQuorumMembers`, which stores the cycles' snapshot rows). Then, for each rotated commitment, both compute the quorum's members, which must agree (`compare_members`, and Core's MEMBERS outcome), and restart; then the two rows digests must agree. Both refusing is out of domain; a refusal on one side only diverges. The model's rows travel in `MinedIndex::snapshot_rows`, and every comparison (`diff_scan_quorums` and `diff_select_quorum`, which seed commitments, and the members targets, uniformly) starts from them, not from empty rows. `seed_mined` keeps its arity for SB8's callers. | O2a-SP seeds rotated commitments signed by their members, so Core's evodb holds every cycle's row after seeding while the model started empty. That is a real difference in state, not a trace artefact: rotated members read the previous three cycles' rows. Starting from empty rows again brings back the failures of `scan_boundary_rows`, `select_boundary_rows` and the public seeds; a model that connects without storing rows diverges at seeding on "member count". Comparing only what both sides hold would have hidden the rows the rotation reads. |
| D39 | `regtest()` in `l1_llmq` loads the fixture's non-rotated commitments only (the same hunk as SB8's). | O2a-SP's `set_mined` refuses a rotated commitment without the snapshot rows its cycle needs, and the fixture holds none. Rotated members read no commitment, so no test there loses a check. The regtest rotation test still connects every block and compares rows and members with `quorum rotationinfo` and `quorum info`. |
