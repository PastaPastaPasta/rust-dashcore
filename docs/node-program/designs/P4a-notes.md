# P4a: inbound policy, implementation notes and D-rows

P4a is the first half of PLAN row P4 ("Inbound full"), split off by the coordinator on 10-17 so
that the parts that need no block store run before P3: `-whitebind`/`-whitelist` permissions
(the full flag set and the legacy `-whitelistrelay`/`-whitelistforcerelay`), bans and
discouragement end to end, P2P-12 (unsolicited GETDATA-only objects), `notfound`,
`-capturemessages`, and three evidence gaps P2b left (P2b D9, D12): eviction across several
netgroups, the verified-masternode eviction exemption, and the exact 8000-header edge of a served
`getheaders2`. P4b (block, filtered-block and compact-block serving, `getblocks`, `merkleblock`
and BIP37, the `NODE_NETWORK_LIMITED` bound, P2P-17, the 125-peer CPU bar) waits for P3.

Core line numbers are the release tag v24.0.0-rc.3's (`0364ed626e`, DEC-82: v24 rules on every
network); `np:` is `net_processing.cpp`, `net:` is `net.cpp`. This file records the implementer's
decisions where the sources leave a choice.
