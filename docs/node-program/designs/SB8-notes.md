# SB8: shared lock and commitment verification, implementation notes and D-rows

SB8 has no design of its own (LQ1 §2.2.4; SB0 §5; EV addendum rev5 m3). This file records the implementer's decisions, per the IMPLEMENTER contract ("decide, record a D-row, continue"). Core references are to v24.0.0-rc.3.

## What landed

- `dash_evo::llmq::verify_commitment` / `verify_quorum` (`llmq/commitment.rs`): Core's `CFinalCommitment::Verify(…, checkSigs)` (`llmq/commitment.cpp` v24:113-209) and `VerifySignatureAsync` run synchronously, with BS12's serial `bls::core`. `verify_quorum` returns a `VerifiedQuorum` (type, hash, index, public key).
- `OperatorKeyView`: the member entry's operator key. `dash_dml::Dmn` implements it (the state's lazy key, `Get()`), and so does `dash_evo::sml::SmlMember`.
- `impl MnListView for SmlList` (`sml/view.rs`): `SmlMember`, and `SmlScratch` (Core's `AddMN` restricted to what the SML carries).
- `UncachedMembers`: a `QuorumMemberSource` over LQ1's `members_uncached` (non-rotated and rotated), for callers without LQ2's cache.
- `dash_evo::locks`: `chainlock_request_id`, `islock_request_id`, `sign_hash`, `QuorumScanView`, `verify_recovered_sig`, `verify_chainlock_sig` / `verify_chainlock`, `islock_trivially_valid`, `verify_islock`.

| D7 | Lock checks take a `QuorumScanView`: the tip height, Core's scan at a selection start block (`ScanLookup::{Held, Unavailable, OutsideHorizon}`), header heights, and `GetQuorum` by hash. Each scan entry carries a `QuorumStatus` (`Verified(VerifiedQuorum)`, `Unverified`, `Unavailable`). Selection (`select_from_scan`, LQ1 §3.9) runs over the whole scan first; only the selected entry's status is read; a non-`Verified` selection is `LockReject::QuorumUnavailable`. | SB0 §5.2 step 6 and DEC-105 F4: a local status costs liveness, never safety, and no other quorum is substituted. `ScannedQuorum::verified` takes the identity from the verified commitment so an entry's hash and index cannot disagree with its key. |
| D8 | Recovered signatures verify one at a time (`verify_insecure` against the selected quorum key over `SignHash`). | Core batch-verifies InstantSend locks (`CBLSBatchVerifier`, insecure aggregation, per-message fallback only when the batch fails). An individual check never accepts what that batch rejects; it may reject what a batch accepts (possible security note: see manager). The per-source effects of a batch (`badSources` skipping a peer's other locks) are P2P policy, not the lock's verdict. For LK1: on a last-pass `InvalidSignature`, Core applies a misbehaviour score of 20 (`OLD_ACTIVE_SET_FAILURE_MISBEHAVIOR_SCORE`), not a ban, once per source per batch (`ApplyVerificationResults`, `net_instantsend.cpp` v24:186-197). |
| D9 | `verify_islock`: the size and `TriviallyValid` checks (`Malformed`), the cycle block by any known header (`UnknownCycle`; a null hash is unknown), the cycle at a multiple of the InstantSend type's `dkgInterval` (`InvalidCycle`), the lazy signature valid under the context (`MalformedSignature`), then two passes: offset 0, then offset `dkgInterval` (`instantsend/net_instantsend.cpp` v24:237-290, :104-170, :330-353). The sign height is `cycle + dkgInterval - 1` when `cycle + dkgInterval < tip`, else -1 (the tip). Rotated types select; a non-rotated type (a regtest `-llmqtypeinstantsend`) looks up the quorum the cycle hash names. Either pass verifying accepts. Otherwise: every pass Core's answer (invalid signature or no quorum) is the last pass's answer (LQ3a D32); else `BlsUnsupported` if a pass had no BLS verdict; else `QuorumUnavailable`; else `OutsideHorizon`. | Core retries only the locks pass 0 marked bad (`net_instantsend.cpp` v24:340-353) (`badMessages`: an invalid signature or no quorum), with banning; a lock is accepted when either pass verifies. A pass whose selected quorum is not verified locally decides nothing, so the combined answer never claims Core's rejection unless both passes are Core's. |

| D24 | The oracle differential covers `Verify`'s structural checks (Opus r1 F3): each applicable mutation is run per sample, and all 13 forms occur across the corpus (nVersion ±1, signers and validMembers sizes, counts below `minSize`, a zeroed quorum key, a null vvec hash, zeroed `membersSig`/`quorumSig`, members ending below a valid bit and at a signer whose valid bit is cleared, another commitment's `quorumSig`), is judged on its re-encoding by Core's `Verify(…, true)` and by SB8, and both the verdict and Core's log line must match the `CommitmentReject`. Mapping: Core's line is `CFinalCommitment -- q[<hash>] ` + the `Display` text, exactly for most reasons, with Core's value appended for five (`invalid quorumIndex=<i>`, `invalid signers.size=<n>`, `invalid validMembers.size=<n>`, `invalid validMembers count. validMembersCount=<n>`, `invalid signers count. signersCount=<n>`), which the variants do not carry; `invalid llmqType=<t>` is a sixth of the same shape, which no structural mutation reaches. The test accepts only that named suffix, a decimal value, for those reasons and an empty suffix for every other (Sol r2). A `quorumIndex` mutation has no non-rotated wire form (versions 1 and 3 carry no index; the field appears only with version 2 or 4, which fails the version check first), so it stays the unit tests' (`a_rotated_commitment_carries_its_index_and_version_4`) until SB11's rotated fixtures. | The values are Core's log detail, not part of the verdict; matching the line's head and reason pins which check failed. |
