# BS11a-2: oracle BLS ops and relic call log, implementation notes

Decision rows taken while implementing BS11a-2, the design's §9 slice 2 (BS11a design rev7.2,
`dc4faa03f`): the §7 ops, flag bits and code field of `oracle_bls_exec` at ABI 19 (Core branch
`node/bs11a-2-oracle-bls-v24.0`), the `dash-oracle-sys` binding, the call log's wrappers and
throw-site check (`contrib/node/oracle-relic/`, run by `build-oracle.sh`), and base-sdk's
`relic.json5` vectors. Program decisions live in DECISIONS.md.

| D47 | The entries that return before reaching `Guarded` take relic's code too. About 60 entry points (among them those that call the session/chain `Hooked` helpers) and the WithContext, WithLlmq and Stateful helpers refuse arguments with `Fail` before their guard, so `::Fail` at guard depth 0 (outside every guard) takes the code first: such a call fails with ORACLE_E_EXCEPTION and clears it, as its guard would have, whatever it refuses. An audit of every exported function (m1r/audit.py, audit2.py) finds no other exit: each either enters a guard, returns through `Fail` or holds a `RelicDrain`.
