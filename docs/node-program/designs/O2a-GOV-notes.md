# O2a-GOV: oracle governance entries, implementation notes

Decision rows taken while implementing O2a-GOV (governance pack proposals C and D): the Core entries
`oracle_gov_proposal_validate`, `oracle_gov_object`, `oracle_gov_vote` and `oracle_gov_ops`, and the payments
context format 2 of `oracle_block_value_payee` (ABI 24 under DEC-238; the train driver assigns the installed number at
stacking; Core branch `node/o2a-gov-oracle-v24.0`); their `dash-oracle-sys` binding (module `gov`,
`Oracle::block_value_payee_scripted`); the L0 vectors (`tests/gov.rs`, `tests/data/gov/proposals.txt`); and the
Core-produced regtest network (`scripts/gov_capture.py`, `scripts/gen-gov-regtest.py`, `tests/gov_regtest.rs`). The
byte formats are in `oracle.h`, "governance (ABI 24; v24 only)" and "Payments context (format 2, ABI 24)". Program
decisions live in DECISIONS.md. `governance/*` is v24.0.0-rc.3's byte for byte at the pin except `superblock.cpp`'s
StateDigest taps (`git diff v24.0.0-rc.3 5c9e9117a2 -- src/governance`), and the line numbers below are rc.3's.

| Row | Decision | Evidence |
|---|---|---|
| D1 | **Four stateless entries plus a payments format, v24 only, additive.** Each call builds its node (D3) from the call's contexts and drops it on return. A non-v24 build returns `ORACLE_E_UNSUPPORTED` (DEC-82). ABI 24 adds entries and a payments context format; every earlier entry is unchanged except format 1's trigger refusals, which D10 narrows to the triggers Core reaches. | `oracle.h` "governance (ABI 24; v24 only)"; `tests/smoke.rs` ABI 24. |
| D2 | **`ValidateProposal()` runs at a given adjusted time on a selected network.** The proposal checks compare `end_epoch` with `GetAdjustedTime()` (`object.cpp:146-149`) and decode the payment address with the selected network's prefixes (`ValidateProposal()`, `object.cpp:1000-1033`), so the entry takes both. The time is bounded to 1 .. `INT64_MAX / 1e9 - 7200`: the upper bound is where `SetMockTime()` and every governance check's `GetAdjustedTime() + 1 h` stay defined, and 0 is refused because `SetMockTime(0)` means no mock time, so the call would run on the wall clock (`util/time.cpp:29-33`; no node's clock is 0). The same bound holds for every governance time: the TIME op, and the chain context's `adjusted_time` in every governance entry and in format-2 payments (Opus r1 F1). Malformed hex is Core's verdict, not a refusal. | `proposal_files_get_core_verdicts` (77 lines, every case of `governance_validators_tests.cpp` including `extreme_end_epoch_is_not_expired`); `proposal_time_and_flag_refusals`. |
| D3 | **A governance call runs in a node at the chain context's tip.** `GovNode`: an active chainstate on the context's headers (`IsCollateralValid()` counts confirmations there, `object.cpp:855-861`), the masternode manager's tip at the context's tip (`GetListAtChainTip()` is the context's list), a valid masternode meta manager (`ProcessVote()` asserts it), and the governance notifications silenced by `--wrap` seams (`NotifyGovernanceObject`, `NotifyGovernanceVote`). `CMasternodeSync` is at FINISHED when the governance context says synced, else GOVERNANCE (`masternode/sync.cpp:64-84`): the unsynced state in which a node's handlers already pass objects and votes on (`net_governance.cpp:82-83`, `:217`; at BLOCKCHAIN they drop them). The managers read only `IsSynced()` on these paths; the `IsBlockchainSynced()` readers (`CheckAndRemove()` and `ConfirmInventoryRequest()`, `governance.cpp:390`, `:613`) are not reached (D7), so the verdicts are the same either way (Opus r1 F4). | `oracle.cpp` `GovNode`, `GovManager`. |
| D4 | **The transaction index is a seam over the context's collaterals.** `IsCollateralValid()` reads only `g_txindex->FindTx()` (`object.cpp:799-802`). The shim installs one never-started `TxIndex` and wraps `FindTx()` to serve the governance context's transactions, each with the block holding it. A collateral's block must be on the context's chain (a header at or below the tip, not a placeholder above it) when it is marked active (`ORACLE_E_CONTEXT` otherwise) and must not be when inactive (a block off the active chain: no confirmations; Opus r1 F6). A null block hash, a repeated transaction and a live transaction index (a chain session's) are refused. An empty governance context is format 1, not synced, with no collaterals. | `oracle.h` "Governance context (format 1)"; `objects_match_node0` (every proposal valid with its collateral); `collateral_confirmations_and_refusals` (1 and 5 confirmations postpone, 6 accept, off-chain rejects; each refusal). |
| D5 | **`oracle_gov_object` records Core's reads and refuses nothing about the object.** It gives the three hashes, the type, `GetMinCollateralFee()`, `IsValidLocally()` without the collateral (what `UpdateLocalValidity()` caches: `fLocalValidity`, `IsValidReason`; it reads no list) and with it (what `ProcessObject()` checks; only a trigger's branch reads the tip's list, `object.cpp:746-766`), and the trigger `CSuperblock`'s parse. Where a field's Core computation would be undefined behaviour the record carries a sentinel instead of refusing, because Core makes those reads only for an object it holds: `payments_limit` -1 where `oracle_superblock_payments_limit` refuses the height, and `expired_*` 2 where the event height plus the status's horizon overflows `int`. The overflow Core does reach is refused in the `AddTrigger()` seam (D8). | `objects_match_node0` (hash, type, data, local validity, fee, the trigger's payments against `getblocktemplate`). |
| D6 | **`oracle_gov_vote` checks the signature against the tip list's key for the vote's outpoint.** It gives the hashes, `GetSignatureString()`, whether `IsValid()` reaches its list lookup (`reads_list`: time at most adjusted time + 1 h, signal and outcome in range, `vote.cpp:213-231`), whether the list holds the outpoint (`mn_found`), and `IsValid()` with the voting key and with the operator key, and `IsValidForUnknownParent()` (`:244-250`: a funding vote tries the voting key, then the operator key). An outpoint the list does not hold is invalid under every key (MG-02: this is where an unresolved outpoint diverges from Core), and `ProcessVote()` then rejects it as PERMANENT with penalty 20: "Masternode … not found" with a known parent (`object.cpp:392-397`), "Invalid vote for unknown parent object …" with an unknown one (`governance.cpp:820-826`). | `votes_check_the_tip_list`; probes "unknown masternode, known parent" and "unknown masternode, unknown parent" in `replay_matches_node0`. |
| D7 | **`oracle_gov_ops`: one manager, the message handlers past their gates.** A fresh `CGovernanceManager` (no cache loaded, so its destructor writes nothing) over a loaded `SuperblockManager`, after `UpdatedBlockTip(tip)`. OBJECT and VOTE take the network message payload: one that does not decode outputs `decoded 0` (a vote's peer is punished 100, `net_governance.cpp:207-212`), else `ProcessObject()` / `ProcessVote()` run and their outcome, exception type, message, penalty and the parent to request are recorded. STATE reads the tallies over the tip's list by voting weight, the cached flags and the current votes; BLOCK runs `IsSuperblockTriggered()`, `GetBestSuperblock()` and `GetSuperblockPayments()`. Not modelled: the handlers' sync, inventory-request and misbehaviour bookkeeping, later tips (postponed objects are not re-processed and nothing expires by height), and `CheckAndRemove()`/`UpdateCachesAndClean()` (the sentinel variables are not recomputed, so STATE's cached flags are the object's as processed, not `gobject get`'s). | `oracle.h` "governance ops"; `ops_refusals`; `replay_matches_node0`. |
| D8 | **Trigger arithmetic is refused in seams on Core's own functions, so only where Core reaches it** (Opus r1 F2, F3). Two `--wrap` seams run while a governance or payments call is on the thread. (a) `SuperblockManager::AddTrigger()` returns `!IsExpired(cachedHeight)` for the trigger it builds, adding `min(576, nSuperblockCycle)` to the event height as an `int` (`superblock.cpp:440-465`, `:340-358`); the seam refuses (`ORACLE_E_ARG`) when that overflows and `CSuperblock` parses, then calls Core's function. Its earlier "already have hash" return is never taken in the oracle: `CGovernanceManager` adds each object once and format 1 refuses a repeated trigger. Objects that `ProcessObject()` turns away before `AddTrigger()` (seen, rate-checked, invalid) are no longer refused, as a first cut that checked every locally valid trigger did. (b) `IsValidSuperblock()` runs `CSuperblock::IsValid()` on the best trigger at the height, which sums its payments unchecked (`GetPaymentsTotalAmount()`, `:238-241`, `:282`) once the height is a superblock height and the coinbase has an output per payment (`:255-280`); the seam refuses exactly that overflow. The block-value sum after it (`:289`) cannot overflow, because the total is at most the payments limit there, so it is not checked. | `oracle.cpp` `CheckTriggerExpiry`, `CheckBestTriggerTotal`; `payments.rs` "an event height IsExpired() overflows" (through the `AddTrigger()` seam). No crafted trigger reaches (b): it needs thousands of payments and coinbase outputs. |
| D9 | **Op fields are read strictly.** A truncated op is `ORACLE_E_ARG` ("op N is truncated"), as is an unknown op code and a TIME outside D2's bound. The record is written only after the whole script ran, so a refusal returns no partial outputs. | `ops_refusals`; `records_parse_exactly`. |
| D10 | **Payments context format 2: the triggers are what a governance script leaves held.** Format 2 replaces format 1's trigger list with a governance context (collaterals) and an op script, run through D7's manager over the same `SuperblockManager` the payments check reads; the fees, sync, ChainLock and loaded flags are format 1's. Both formats refuse the trigger arithmetic only in D8's seams, so only for what Core reaches. The first cut checked the sums of every held trigger, a superset of Core's reads (Opus r1 F2); format 1 had done the same since O2a-GV, and narrowing it there only turns refusals into Core verdicts. `block_value_payee_scripted` refuses a context with format-1 triggers. | `superblock_payments_under_a_script`: the mined superblock is valid under node 0's objects and votes, equal to the format-1 answer, and overpays (`value_valid` false, derived from `IsBlockValueValid()`, not captured) without the trigger's votes. |
| D11 | **L1 evidence comes from Core's own functional-test framework on the release binary.** `gov_capture.py` is a `DashTestFramework` test (rc.3's framework, byte-identical) on dashd v24.0.0-rc.3: four masternodes and two evonodes, four proposals (one left unvoted), every vote signal, a trigger the masternodes create and vote on, and twelve votes delivered over P2P (`inv`, node 0's `getdata`, `govobjvote`) with the verdict node 0 logged. InstantSend is turned off, as in `feature_governance.py`, because unlocked transactions are not mined while it is on (the collaterals would never confirm). The objects and signed votes replayed are node 0's own, read from its `governance.dat` with dash-coreimport's IM1b reader (a dev-dependency; T may depend on N). | `tests/data/PROVENANCE.md` "Governance regtest network"; `replay_matches_node0`. |
| D12 | **Each probe is replayed at the time node 0 logged.** `ProcessVote()` reads `GetAdjustedTime()` for the rate check and `IsValid()` for the future bound, so the replay sets TIME to the mock time on node 0's receipt line. The captured vote an hour ahead is exactly at the bound (+3600 s) and accepted; `gov_vote` reproduces it only at node 0's clock, so that test runs at the last probe's time. | `probe_time`; "a vote from the future". |
| D13 | **What the regtest test compares, and what it does not.** Compared with Core: every probe's verdict, full exception message (type prefix included; an accepted vote carries the default exception, "GOVERNANCE_EXCEPTION_NONE:") and misbehaviour score; each object's weighted tallies (evonodes weigh 4) and current votes as `gobject getcurrentvotes` prints them (outpoint, creation time, outcome, signal), before and after the probes; and the best trigger's payments. Not compared: an instance's `last_update` (the replay's clock, not node 0's) and the cached flags (D7). The parent to request is checked against the vote's parent after the unknown-parent warning (`governance.cpp:827-838`: set when the orphan vote is newly cached). | `check_state`, `replay_matches_node0`. |
| D14 | **Opus r1 (CHANGES REQUIRED) is applied.** F1 time 0 (D2), F2 and F3 the trigger seams (D8, D10), F4 the unsynced state (D3), F5 the format-2 doc (no `ExecuteBestSuperblock()` runs on a held trigger: `UpdatedBlockTip()` runs before any op), F6 active collaterals by ancestry (D4), F7 `mn_found`'s doc (0 when the list is not read), F8 the collateral and time tests, F9 the citations, F10 the Rust parsers (a payments limit must be 0 off a superblock height and -1 or at least 0 on one; the error string must hold exactly one NUL). Postponed objects are evidenced through `gov_object`'s `missing_confirmations`, the flag `ProcessObject()` postpones on (`governance.cpp:251-266`); an op script needs the tip's list, which the capture holds only at block 179. | `collateral_confirmations_and_refusals`, `proposal_time_and_flag_refusals`, `ops_refusals`. |
| D15 | **Opus r2 ACCEPT.** The re-check confirmed the seams fire only where Core reaches the arithmetic, that both wraps are linked (callers in other translation units; `build-oracle.sh` derives `--wrap=` from the shim's `__real_`/`__wrap_` pairs), that the flag is scoped by RAII, and found no regressions. Its four comment and note nits are applied. | Review r2. |
