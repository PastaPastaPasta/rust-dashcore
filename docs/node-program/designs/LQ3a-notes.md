# LQ3a: the `qsigrec` verdict and the lock messages' wire forms, implementation notes and D-rows

LQ3a is the first slice of LQ3 in `dash_evo::locks`. It covers two things. The first is Core's verdict on a `qsigrec`: the type check, `IsQuorumActive` over the scan at the tip, the by-name quorum check, and `GetRecoveredSigForGetData`'s active-quorum check. The second is the inventory hashes and signature reads of `clsig`, `isdlock` and `qsigrec`. The recovered-signature database, its cleanup and the listeners are not in this slice. This file records the implementer's decisions, as the IMPLEMENTER contract requires ("decide, record a D-row, continue"). Core references are to v24.0.0-rc.3.

## What landed

- `dash_evo::locks::recsig`:
  - `verify_qsigrec` returns a `RecSigVerdict`: `Accept(VerifiedQuorum)`, `Ignore(RecSigIgnore)` or `Ban(RecSigBan)`.
  - It returns `RecSigError` when the view does not decide.
  - Also here: `is_quorum_active` (Core's `IsQuorumActive`) and `serves_recovered_sig` (the active-quorum half of `GetRecoveredSigForGetData`).
- `dash_evo::locks::wire`:
  - `RecoveredSig`: the `qsigrec` payload, with `decode`, `hash` and `sign_hash`.
  - `clsig_hash` and `isdlock_hash`.
  - `read_eager_sig` / `read_lazy_sig`, which return a `SigRead` (`Unreadable`, `Invalid` or `Valid`).
- The schemes each check reads, as named fields: `LockSchemes`, `IslockSchemes` (with `IslockPassSchemes`) and `ClsigHashSchemes` (D26).
- `QuorumScanView::scan_at_tip`: Core's `ScanQuorums(type, count)` at the tip.
- Quirk 38 is tested in `dash-evo/src/locks/wire_tests.rs` (register status "tested"), and its conformance scaffold is gone.
- `contrib/node/lq3a-captures`: a Core functional test that records the `qsigrec`, `clsig` and `isdlock` messages a v24 regtest network relays, each with the inventory hash Core announced. Its output is `dash-evo/tests/data/lq3a-regtest-captures.json`, read by `dash-evo/src/locks/capture_tests.rs`.
