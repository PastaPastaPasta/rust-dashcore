# P4b: inbound serving, implementation notes and D-rows

P4b is the rest of PLAN row P4 ("Inbound full") after P4a (`P4a-notes.md`, merged in T18):
block serving (`getdata` MSG_BLOCK, MSG_FILTERED_BLOCK and MSG_CMPCT_BLOCK, `getblocktxn`),
`getblocks` with its `hashContinue` inv, `merkleblock` with BIP37 and Dash's special-transaction
bloom matching, the `NODE_NETWORK_LIMITED` serving bound, O17's P2P-17 (a block read racing a
prune) and the 125-peer CPU bar.

Core line numbers are the release tag v24.0.0-rc.3's (`da567d7dba`, DEC-82: v24 rules on every
network); `np:` is `net_processing.cpp`, `bloom:` is `common/bloom.cpp`, `mb:` is
`merkleblock.cpp`, `std:` is `script/standard.cpp`. This file records the implementer's decisions
where the sources leave a choice.

## Test plan

**Unit tests** (in-module):
- `bloom`: Core's `bloom_tests.cpp` vectors (`bloom_create_insert_serialize`, `_with_tweak`, `bloom_match` for P2PUBKEY_ONLY and UPDATE_ALL, the empty "match-all" filter) and Dash's special-tx cases from `evo_*`/`bloom_tests.cpp` where they exist; `IsWithinSizeConstraints` at 36,000/36,001 and 50/51; since review r1, `bloom::tests::v24` for every special-transaction arm past the DIP2 types (D17).
- `dash_p2p::policy`: `filterload`'s and `filteradd`'s pre-read `LIMITED_VECTOR` rows at 36,000/36,001 and 520/521, the count alone, and a filter cut short after `vData` (D7).
- `merkle`: `merkle_tests.cpp`'s `pmt_test1` shapes (1, 4, 7, 17, 56, 100, 127, 256, 312, 513, 1000, 4095 txs; random match sets) round-tripped through `ExtractMatches`; `CMerkleBlock` `allowedTxTypes`.
- `serve_blocks`: the decision table of `process_get_block_data` over a scripted `ChainAccess`: unknown, not allowed, limited bound (290 served, 291 disconnects; `NoBan` exempt; `NODE_NETWORK` present exempt), `!HAVE_DATA`, `Pruned`, `Failed`, the three types, continuation.

**Sim ports** (`tests/sim_serve_blocks.rs`, the `sim` network with rdashd's processor): `p2p_filter.py` (size limits; filterload/filteradd/filterclear; filtered block with and without a filter; `relaytxes`), `p2p_node_network_limited.py` (pruned sim node: services, 288+2 bound, disconnect), `p2p_getdata.py` (an unknown type is dropped; a following ping is still answered), `p2p_compactblocks.py`'s `test_getblocktxn_handler` and the `getdata(MSG_CMPCT_BLOCK)` depth rule, `p2p_blocksonly.py`'s serving side (a block-relay-only peer's filterload, filteradd and filterclear are taken without a score and store nothing; its `MSG_FILTERED_BLOCK` gets no reply), `getblocks` from a peer whose `CanRelay()` is false (an outbound masternode connection: no `inv`, the continuation kept).

**O17 P2P-17 race test:** the sim chain prunes the requested block between the `HAVE_DATA` test and the read (a hook in the sim chain's `read_block`): "Block was pruned before it could be read" and a disconnect; a read failure without a prune gives "Cannot load block from disk" and a disconnect. A prune marked between the decision and the read with the block still stored is served (D16). A `NodeChain` test faults the real block file (D3).
