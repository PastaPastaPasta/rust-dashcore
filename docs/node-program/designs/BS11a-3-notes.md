# BS11a-3: engine groups and IES, implementation notes

Decision rows for BS11a-3, the design's §9 slice 3 (BS11a design rev7.3, `BS11a-legacy-bls.md`):
- the relic engine's field layer, recoding, G1/G2 operations and `mul`;
- `SerializeToArray`;
- `BlsElem` (`from_impl`, `aggregate_insecure`; F11, D63) and `BlsValue`'s arithmetic-result element (D69);
- `ies_key`, the Chia KDF fix and the KAT regeneration;
- the `bls_engine_model` and `diff_bls_arith` targets.

These rows settle what §9 leaves open. Program decisions live in DECISIONS.md, and design D-numbers are cited as "design D*n*".

## Certification budget (DEC-184/186)

Both targets run as bounded units at Nice 19 (`fuzzctl` farm slices with plateau stop, `--plateau-minutes 60`).

- **Plateau rule.** A leg stops on a plateau; nothing is sized in CPU-hours.
- **Certification.** Each target is certified by `fuzzctl certify <target>@v24.0`: the 60-minute window on the merged corpus. The gate needs 0 divergences, 0 crashes and, for `diff_bls_arith`, 0 relic codes.
- **Expected rates.** `bls_engine_model` runs about 10⁴–10⁵ exec/s with the default `min_certify_execs` (10⁶). `diff_bls_arith` is bound by the oracle at about 10²–10³ exec/s with 2·10⁵.
- **Low-ceiling plateau.** It triggers DEC-184 (3)'s review against §8's engine branch list: G1 mixed vs general add (equivalent, D30: needs no seeds); the infinity and zero-z paths; G2's H = 0 / R = 0 branches; `mul_dig` vs LWNAF; the GLV/GLS sign cases; `ep*_norm_sim`'s zero batch. An unhit branch gets targeted seeds or a structured class, not more hours.
- **Ceiling.** One rework round per target before the manager is asked.

## How slice 4 attaches

- **Miller loop.** `bls::relic::pp` ports `pp_map_sim_oatep_k12`, `pp_mil_k12` and the LAZYR line functions over the Fp6/Fp12 layer it adds (D2). It takes its operands from `BlsElem` through D8's dispatch. `pp_map_sim` normalizes, so a Group operand enters as its affine point, as T′ (d) allows.

- **Verify branch.** The engine branch sits inside BS12's serial verify behind `BlsPoint::usable()`, the existing conversion test. `bls::core::{verify_insecure, verify_insecure_aggregated, verify_secure_aggregated}` return `Unsupported` today for legacy-flag Exotic operands; slice 4 replaces exactly those returns.
- **Secure verify.** `verify_secure_aggregated`'s legacy Σ tᵢ·Pᵢ becomes `BlsElem::mul`/`add` in sorted order, starting from the default element. Under the basic flag it keeps the blst sum.
- **Oracle.** `diff_bls_verify` reuses this slice's register builder and op encoder from node-l1.

## How BS11b's API attaches

BS11b composes on `bls::core`:
- `BlsElem::{from_impl, add, neg, mul, core_eq, is_valid, to_bytes, aggregate_insecure}` and `BlsValue::core_eq` (D25);
- `From<BlsElem> for BlsValue` (D9) and `BlsValue::invalidate`;
- `BlsElem::mul_secret_value`, crate-visible, for a secret scalar's product (D34);
- `ies_key`.

`mul`, `to_bytes` and `From` are variable-time on every element, so they are for public scalars only. To dedupe as Core's `std::set`/`std::map` do, key by `to_bytes(scheme)`, not by `BlsValue` (D25).

What BS11b ports:
- **`PublicKeyShare` and `Recover`:** `mul`/`add` chains in dashbls's order (`threshold.cpp`). The order is part of the value off the curve (design D63; A-10).
- **The in-place receivers** (`SecretKeyShare`, `PublicKeyShare`, `Recover`, `DHKeyExchange`): `invalidate` on a `false` return, `From<BlsElem>` on success. `DHKeyExchange` instead assigns `from_impl(pk).mul_secret_value(sk's stored bytes)`, which is that same wrapper (D34).
- **Multi-recipient IES:** `ies_key` per recipient.
- **Secret-key arithmetic** (`SecretKeyShare`, span `AggregateInsecure` of keys): `Fr` and its own `repr` (D6).

BS11b needs no engine access beyond `BlsElem`.
