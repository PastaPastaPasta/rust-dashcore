# R2b — Dash Core RPC inventory (develop @ 15db478750, v24.1.0-pre)

Companion to `R2-dashcore-inventory.md` (section B). Generated by parsing every `CRPCCommand` table under `src/` (`src/rpc/*.cpp`, `src/wallet/rpc/wallet.cpp`, `src/zmq/zmqrpc.cpp`) and resolving each actor to its `RPCHelpMan` name + description; wrapper-generated commands (protx register*/update_registrar*, gobject list/diff, masternode list, echo) were resolved by hand. READ-ONLY extraction; nothing in the repo was modified.

**Totals:** 292 table rows / 289 distinct command names (incl. dispatcher/help entries such as `protx`, `quorum`, `gobject`, and hidden/test-only commands). 115 are Dash-specific (not in Bitcoin Core). Per category: wallet=71, evo=51, dash=39, blockchain=36, hidden=32, rawtransactions=21, network=13, util=8, control=7, mining=7, addressindex=5, zmq=1, signer=1.

**How Dash RPC naming works (must replicate for dash-cli compatibility):** Dash registers multi-word commands such as `"protx register"`, `"quorum sign"`, `"gobject vote-many"`, `"masternode status"`, `"coinjoin start"`, `"coinjoinsalt get"`, `"bls generate"`, `"evodb verify"`. `CRPCTable::execute` (`src/rpc/server.cpp`) first tries `method + " " + params[0]` as a command name and, if registered, shifts params by one. So `dash-cli protx info <hash>` is JSON-RPC `{"method":"protx","params":["info","<hash>"]}`. Named-argument and positional semantics must match `RPCHelpMan` definitions exactly (including the `skip_type_check` string-or-number quirks used by protx/gobject).

**Registration paths:** node-side tables are registered by `RegisterAllCoreRPCCommands` (`src/rpc/register.h`). Wallet-side tables (`GetWalletRPCCommands`, `GetWalletEvoRPCCommands`, `GetWalletGovernanceRPCCommands`, `GetWalletMasternodeRPCCommands`, `GetWalletCoinJoinRPCCommands`) are registered through the wallet interface (`src/wallet/interfaces.cpp`) only when the wallet is compiled/enabled, and are reachable on `/wallet/<name>` endpoints. `commands_wallet` variants (`protx list/info`, `getcoinjoininfo`) are wallet-aware overrides of node commands. `walletdisplayaddress` exists only with `ENABLE_EXTERNAL_SIGNER`. `generate*` work only when built with the internal RPC miner (default for regtest/test builds); otherwise they return "not available". Platform-facing RPCs (`quorum platformsign`, `getbestchainlock`, `quorum verify`, `getassetunlockstatuses`, etc.) are what Dash Platform (Tenderdash/drive) calls; operators usually restrict that RPC user with `-rpcwhitelist` (whitelist entries may name a subcommand as `method`+`params[0]` concatenated without a space, e.g. `quorumsign` — `src/httprpc.cpp:106-112`). `-rpcexternaluser` only routes listed users to a separate HTTP work queue (`-rpcexternalworkqueue`), it does not restrict them.

**User-story buckets:** node-ops, wallet, masternode-operator, governance, mixing, platform, mining, debugging, indexes, integrator (exchange/explorer via RPC). Combined buckets (e.g. "platform / masternode-operator") mean both personas rely on it.
