## Finding

### Nit — finish the deferred census check before declaring success

**Location:** `contrib/node/perfgate/perfgate/outer_init.py:170-176` and `:249-303`.

**Failure scenario:** D104 records an unregistered process seen in the root cgroup and skips it until a later full pass. The run loop can reap the view and broker and break before its next 0.25 s census timer; it then writes `outer.json` and may return success without judging that still-live identity. For example, if an unexpected outer-namespace process first appears in the root cgroup on the last scan and remains there while both registered children exit cleanly, the promised later pass does not happen. I found no route for a normally confined PR node to enter the outer PID namespace or move itself to the root cgroup; this is a completeness gap in the census, not a demonstrated sandbox escape. **Suggested fix:** Before a successful return, require one later full census pass for any still-live `unplaced` identity, bounded by the invocation's existing deadline, and test the broker-exit-before-next-tick case.
