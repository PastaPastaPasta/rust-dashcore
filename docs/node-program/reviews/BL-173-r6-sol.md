# BL-173 narrow review — Sol r6 (fe00de689, D17)

## Findings

1. **Major — A worker's output can forge the parent's missing exit line, so the new count is not sufficient proof of a complete log inventory.** `node-fuzz/fuzzctl.py:524-535,565-570`; `node-fuzz/fuzzctl.py:1211-1248`. `JOB_EXIT.finditer(parent)` scans the parent's whole `fuzz.out`, including the worker logs that the parent copies into it, and `named` discards duplicate marks. In a two-worker scratch run with a valid `jobs` file (`2\n`), worker 0's log began with a marker-shaped `Job 1 exited with exit code 70` line and then its interrupted empty `timeout-0123` write. The parent had its real Job 0 line followed by that worker-0 text. Worker 1 had timed out for real on the same empty input, but its `fuzz-1.log` was cut to an empty present file and the parent was cut before its real Job 1 line/copy. The fake line supplied `named={0,1}`; the exit-70 guard found worker 0's write in both apparent sections. `logs_complete` returned true, `phantom_timeouts` returned `['timeout-0123']`, `run_findings()['crashes']` returned 0, `findings_of` returned no finding, triage counted one harness event and no finding, and `Farm.accounted` returned `interrupted`. A recorded `fuzz-0.log` hit also passed `verified_hit`/`phantom_verdict`. This requires a marker-shaped line in child output plus the log loss, but the parser currently treats child text as authoritative parent framing; no guard establishes that those lines came from libFuzzer's parent. **Fix:** make the exit inventory unambiguous: reject marker lines appearing in worker logs, require exactly J parent marks rather than only a matching set, and fail closed when the parent copies cannot be reconciled with those worker logs (or record exits through a separate structured channel). Add the forged-marker/truncated-parent regression test.

2. **Minor — A malformed `jobs` file can abort the consumers instead of yielding a finding.** `node-fuzz/fuzzctl.py:494-501`. `segment_jobs` reads text without a size or decoding bound, then calls `int` outside the `OSError` handler. A forged file of 5,000 digits plus a newline raises Python's integer-conversion `ValueError`; invalid UTF-8 raises `UnicodeDecodeError`. Both reach `run_findings` and `findings_of`, and `Farm.accounted` propagates them; triage records a run error instead of accounting for the saved timeout. These files are not produced by `run.sh`, but D17 describes invalid count contents as no count and the requested positive-proof rule calls for doubtful evidence to retain the finding. **Fix:** read a small bounded byte string, decode it as ASCII, and return 0 on any invalid, excessive, or unreadable value.
