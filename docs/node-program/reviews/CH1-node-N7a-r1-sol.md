# CH1-node N7a, round 1 — c89bb1d01

## Findings

**R1-m-1 (minor) — `docs/node-program/designs/CH1-node-notes.md:41`; `dashd-chainstate/src/chain/flush.rs:188`.** D47 says to build `FlushCx` per call from `FlushHost::tip()`, but the latter is `None` until genesis connects, while `FlushCx::tip` is a required `BlockRef` (`dashd-chainstate/src/flush/control.rs:93-95`). Genesis's `ConnectTip` therefore reaches an IF_NEEDED site with no tip, and the devnet genesis AcceptBlock reaches a NONE site in that state. An adapter that unwraps there aborts startup; one that supplies the genesis block as a synthetic tip could answer a pending `PruneClears` against the wrong height. Core's prune selectors return before selection with no active tip (`v24.0.0-rc.3 node/blockstorage.cpp:170-172, 190-195`), and Core's devnet AcceptBlock runs before init's ABC (`validation.cpp:5409-5416`). **Fix:** make D47 require an explicit no-tip path that declines queued clears without an unwrap or a fabricated tip; if a decision is needed at that site, let the context represent the absent tip. Add a committed pre-init regression. The current model W already declines correctly; my scratch pre-init probe observed `answered_at == [None]` and `Declined`.

**R1-m-2 (minor) — `docs/node-program/designs/CH1-node-notes.md:41`; `dashd-chainstate/src/chain/flush.rs:49-55`.** D47's adapter list should require a service-only CH2b entry point and a `FlushReleases::hand_to` on every adapter return. The currently public `FlushControl::poll` (`dashd-chainstate/src/flush/control.rs:283-294`) drains events **and may freeze a pending cause**; CH2b's event-only `service` is private (`control.rs:467-472`). Using `poll` to implement `FlushSite::service` at V's bell waits changes D44's no-freeze contract and Core's flush-site ordering (`validation.cpp:3303-3306, 3456-3459`). Merely supplying `FlushReleases` as the port also leaves released tips buffered until `hand_to` runs; Core signals after a completed full flush (`validation.cpp:3110-3115`). **Fix:** implement the adapter where it can invoke event-only service, or expose that method; hand the port's tips to `FlushHost` on success and error before each call returns. Keep the existing D47 requirements for driver bell rings and `retry_pending` during `wait_release`. This is an integration requirement; N7a currently runs with `NoFlush` or the model W.
