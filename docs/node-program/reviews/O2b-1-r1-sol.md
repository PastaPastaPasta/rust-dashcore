# O2b-1 Core chain-session oracle shim — Sol r1

**Verdict: CHANGES REQUIRED**

1. **MAJOR — A load can choose which failed branch to reconsider by unordered-map order, without taint.** `src/validation.cpp:5458-5480` builds `vSortedByHeight` from the unordered block map, sorts only by height, and retains the first equal-work failed entry as `m_best_invalid`. `VerifyLoadedChainstate` then calls `ResetBlockFailureFlags(nullptr)` at the default check level 3 (`src/node/chainstate.cpp:463-465`), which uses that entry to choose a branch (`src/validation.cpp:4265-4270`). Two equal-work failed branches can therefore yield different failure bits, candidate sets, and a different activated tip after the same image is loaded. Site 2 only examines valid best-header contenders and does not cover this choice. **Fix:** taint the load when the maximum-work failed block is tied and the chosen `m_best_invalid` can reach the reset path; add a regression with two equal-work failed branches whose flags are persisted before reload.

2. **MAJOR — ChainLock enforcement iterates siblings in an unreported unordered order.** `m_prev_block_index` is an `unordered_multimap` (`src/node/blockstorage.h:59`) rebuilt from the unordered block map on load (`src/node/blockstorage.cpp:287-291`). `EnforceBlock` calls `MarkConflictingBlock` for every sibling in that map's `equal_range` order (`src/validation.cpp:4167-4180`). Each call can disconnect the active branch and emits tip callbacks (`src/validation.cpp:4199-4252`). With a locked branch and at least two competing siblings, the event sequence, and potentially the intermediate tip and reject/log text, depend on that order; none of sites 1–11 taints it. **Fix:** add a tie site at this sibling walk when at least two actionable siblings exist, and cover `CL_ENFORCE` after a reload with an active sibling and another competing sibling.

3. **MINOR — Refuse startup stop options that the session cannot represent.** `StartChain` accepts `-stopafterblockimport` and nonzero `-stopatheight` (`src/test/oracle/oracle_chain.cpp:1171-1175`). Core's `ThreadImport` calls `StartShutdown()` for the former (`src/node/blockstorage.cpp:972-975`), but `Open` only runs its `ActivateBestChain` portion (`src/test/oracle/oracle_chain.cpp:838-855`), so it reports a live session where dashd stops. The latter calls `StartShutdown()` in `ActivateBestChain` (`src/validation.cpp:3938-3940`), which the shim converts into a broken-session exception instead of a modeled stop. **Fix:** return `ORACLE_E_ARG` for `-stopafterblockimport=1` and nonzero `-stopatheight`, and document those refusals in `oracle.h`.

**Other checks:** Load and reload run `ActivateBestChain` with `fImporting` set (`src/test/oracle/oracle_chain.cpp:838-847`), as `ThreadImport` does. CLEAN performs both of Shutdown's `ForceFlushStateToDisk` calls (`src/test/oracle/oracle_chain.cpp:862-880`), and refused loads use that path (`:764-768`, `:833-836`). The reordered destruction keeps referenced objects alive through the flush. The program runner sets mock time before restoring its image (`src/test/oracle/selftest/chain_selftest.cpp:540-547`). The ABI 17 number and prior function signatures remain unchanged; the new interface is additive and symbolic in its heading. The `m4` missing-env refusal is unsuitable for an early refused load; the `m5` report-bound fallback follows `PendingOutput`, and construction inside `catch_exceptions` has no separate correctness issue. I found no additional lifetime defect in the reviewed new/free/restore and fault-teardown paths.
