CHANGES-REQUIRED

Reviewed rust-dashcore `cde35d9f` against `5714489d`, and Core `c6c2645a42` / `4868aa0cf7` against their specified oracle-shim bases. References below are to those exact Core commits. Evidence and standalone reproduction inputs are in `/work/scratch/o2a-gpt/`.

1. **Major — missing masternode context becomes a consensus rejection.** Location: Core `src/test/oracle/oracle.cpp:932` and `:1832`, both pins; Rust `dash-oracle-sys/src/context.rs:54` permits `mn_list: None`. The constructor leaves EvoDB empty when the list is omitted, but `check_special_tx` still invokes handlers that read it. Core then bootstraps an empty list instead of the adapter reporting missing context. Concrete input: mined mainnet ProUpServTx `8e5bdc5fc72ec8ff125e313bfe65ebcf7b022ce00957a449eeb4b6143edc90f2`, height **1028257**, with its parent's headers and otherwise identical contexts. Both pins accept with the parent list supplied and reject with `bad-protx-hash` when the list bytes are omitted. See `missing-list-results.json` and `missing-list-*-input.json`. Core citations: v24 `src/evo/deterministicmns.cpp:826–885`, `src/evo/specialtxman.cpp:1338–1341`; v23 `src/evo/deterministicmns.cpp:790–817`, `src/evo/specialtxman.cpp:1081–1084`. **Fix:** distinguish explicitly supplied empty state from absent state; return `ORACLE_E_CONTEXT` before a handler reads an absent list. Add this regression at both pins, including a duplicate-registration case that would otherwise become a false acceptance.

2. **Major — header checks silently omit later known checkpoints.** Location: Core `src/test/oracle/oracle.cpp:897` and `:2026`, both pins. The adapter populates the block map only with the ancestry window ending at the supplied parent. Stock `ContextualCheckBlockHeader` also reads checkpoints known elsewhere in the node's block map, including checkpoints later than that parent. Concrete input: the fixture's mainnet header at **1028161**, with byte 36 of its merkle root XORed with 1, its original parent window, and adjusted time 1800000000. Both adapters return `ORACLE_OK` (`checkpoint-omitted-*-input.json`). On a stock node that knows checkpoint **1364585**, the same contextual function returns `BLOCK_CHECKPOINT / bad-fork-prior-to-checkpoint`. This stock-side conclusion follows directly from the pinned code; I did not submit this header to a shared oracle. Core citations: v24 `src/validation.cpp:4493–4501`; v23 `src/validation.cpp:4126–4135`; both pins' mainnet checkpoint tables contain height 1364585. **Fix:** include the node's checkpoint-enabled setting and known checkpoint state in the context and construct the corresponding block-map entries. Until supported, refuse calls whose verdict depends on that omitted state; document any deliberately checkpoint-disabled comparison as such. The existing matrix's checkpoint gap must include this branch inside the contextual function.

3. **Major — malformed MN state escapes the refusal checks and reaches signed overflow.** Location: Core `src/test/oracle/oracle.cpp:733–761` and `:1862`, both pins. `ReadDmn` checks the reserved internal ID but not the state fields used in arithmetic. Concrete input: the supplied parent list from finding 1, with its first MN's `nRegisteredHeight = INT32_MIN` and `confirmedHash = 0`; call `dml_apply` on a coinbase-only block. Both pinned archives return `ORACLE_OK` (`registered-height-overflow-*-input.json`). Core evaluates `1028256 - (-2147483648)` in an `int`, which cannot be represented. Core citations: v24 `src/evo/specialtxman.cpp:333–341`; v23 `src/evo/specialtxman.cpp:207–215`. This is a source-proven undefined operation; the plain-build acceptance is not a UBSan result. **Fix:** validate the supplied MN state's arithmetic preconditions before invoking Core, using wider arithmetic to check subtraction and counter additions. Refuse impossible heights/counters with `ORACLE_E_ARG`; add sanitizer-backed regressions for this input and PoSe-penalty addition boundaries. These are adapter-input guards, not changes to Core consensus functions.

Independent validation: **57/57 crate tests passed**; **50/50 sampled mainnet listdiffs matched per pin** (seed 829361, maximum height 1377874), with sequential read-only RPC requests. Private regtest processes using the pinned dashd binaries exercised two adversarial inputs per contextual operation: special-tx versions, DML unsafe-version refusals, input value/maturity, height/time sequence locks, unknown tx types, old/future headers, coinbase type/finality, and commitment version/bitset size. The 32 adversarial comparisons plus two accepted block baselines are in `regtest-results.json`; rejection reasons agree where the same validation stage returns a reason. DML's documented argument refusals precede the node's special-tx rejection; commitment verification exposes Core's bool/log rather than the outer block rejection class.

The `ld --wrap` seam is thread-local during contextual calls, restored on exit, and falls back to the real function outside them. Its reachable uses here are commitment verification and DML punishment; I found no present leak into a path needing real member selection. Supplied members remain a caller obligation, including Core's empty-member gates. The trampoline patches only append direct calls to unchanged static functions. The pin-specific signatures, special-tx rules and v23/v24 listdiff rendering are correctly selected. C++ exceptions are caught at the outer ABI guard; finding 3 concerns arithmetic that exception handling cannot catch.

Deviations: the mempool-only `check_special_tx` is acceptable as a precisely named partial adapter, with MNHF/AU refusals preserved; it does **not** satisfy PLAN's full block-path promise. Deferring `block_value_payee` for a separately designed governance/sync/spork context is technically reasonable, but payment arithmetic and DML payee selection cannot replace it. Before declaring O2a complete, the manager must accept these scope changes and put the proposed O2a-GV/O2a-LQ1 dependencies into the plan, blocking their consumers' gates until delivered. The pre-V19 sample establishes neither basic-BLS nor rotated-quorum fidelity. Existing sigops coverage from O1b is an acceptable reuse under DEC-25(3); deriving penalties from Core's result classes is also acceptable where Core exposes no separate DoS field.

The v24 plain reproducibility rerun was started with four jobs per root after checking load; it remains in progress at this report's initial write, so no independent reproducibility success is claimed yet. Both private regtest nodes were stopped and no reviewer-started dashd remains running. Neither reviewed checkout was modified.

Summary: useful direct Core adapters and good pre-V19 evidence, but missing state can currently produce authoritative false verdicts, and an unchecked context reaches undefined arithmetic. **Final verdict: CHANGES-REQUIRED.**
