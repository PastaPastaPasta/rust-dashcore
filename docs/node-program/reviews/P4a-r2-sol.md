# P4a inbound policy review, round 2

**Verdict: CHANGES REQUIRED for scoped IPv6 socket parity.** The r1 P2 numeric IPv4 schedules and P3 `qfcommit` hash test are fixed. I reviewed `021cbd885..4c8acd8dc` in a detached worktree against Dash Core v24.0.0-rc.3 (`0364ed626e`); I made no branch edits.

## Finding

1. **P2 — Accepted scoped IPv6 addresses lose their interface before bind or dial.** `dash-p2p/src/lookup.rs:48-52` reads `sin6_addr` but discards `sin6_scope_id`. `NetAddr` has no scope field (`dash-p2p/src/netaddr.rs:65-71`), and `Service::to_socket_addr` creates an IPv6 `SocketAddr` with scope zero (`dash-p2p/src/netaddr.rs:719-730`). The exposed listener and dial paths pass that socket address to the OS (`dashd-net/src/binds.rs:75-83,165-175`; `dash-p2p/src/netcore.rs:927-932`). Core instead copies `sin6_scope_id` from `getaddrinfo` into `CNetAddr` (`src/netbase.cpp:80-89`; `src/netaddress.cpp:299-302`) and sets it on the socket address (`src/netaddress.cpp:881-891`) used by bind and connect (`src/net.cpp:3768-3775`; `src/netbase.cpp:629-645`). **Failure schedule:** on a host with link-local address `fe80::1234` assigned to `eth0`, parse `-whitebind=[fe80::1234%eth0]:19999` and pass its service in `BindOptions.white_binds` to `init_binds`; alternatively dial a peer at `-connect=[fe80::1234%eth0]:19999`. Core supplies `sin6_scope_id=if_nametoindex("eth0")`; P4a parses the same address but supplies zero, so the scoped bind or connection cannot select that interface. This is the operational consequence of D20's known scope gap; D20 names scoped bind, while the dial consequence also needs to be accounted for. Preserve the scope through `Service` and socket conversion, or explicitly exclude these accepted forms from the parity claim until that is implemented.

The loss of scope does **not** change the ban or whitelist match: Core's `CNetAddr::operator==` and ordering ignore scope (`src/netaddress.cpp:610-617`), and `CSubNet::Match` compares address bytes under the mask (`src/netaddress.cpp:1024-1050`), as P4a does (`dash-p2p/src/netaddr.rs:830-841`). A scoped `setban` or Core banlist entry does change its displayed and saved `address` from `fe80::X%N/128` to `fe80::X/128` in P4a; reloading that text keeps the same match set. Core's `CSubNet::ToString` preserves the numeric scope in the text (`src/netaddress.cpp:1052-1082`). This text difference is already documented in D20.

## Checks

- `numeric_host` uses Core's `AF_UNSPEC`, `SOCK_STREAM`, `IPPROTO_TCP`, `AI_NUMERICHOST`, null service, IPv4/IPv6 family filter and first usable result (`dash-p2p/src/lookup.rs:19-59`; Core `src/netbase.cpp:44-95,147-174`). `pre_lookup` performs NUL and special-address checks first, then numeric lookup and internal-address refusal (`dash-p2p/src/seeds.rs:60-75`). `Lookup`, `LookupHost`, and `LookupSubNet` retain Core's port, bracket and netmask flow (`dash-p2p/src/lookup.rs:77-119`; Core `src/netbase.cpp:176-217,760-794`). `-0` is rejected as a port or unsigned prefix; the resulting whitebind/whitelist error paths match Core's `SplitHostPort` and `ParseUInt8`. Refused whitebind and whitelist inputs retain Core's error texts (`dash-p2p/src/permissions.rs:52-71`; Core `src/net_permissions.cpp:84-124`). The P4a call sites (`-whitebind`, `-whitelist`, `setban`, banlist load) and SB6's `-connect`, `-addnode`, seeds and `lookup_numeric` reach `pre_lookup`; `setban` subnet forms reach `LookupSubNet` and its second numeric lookup for a full netmask.
- The unsafe block is sound under libc's `getaddrinfo` contract: `CString` rejects interior NUL, the zeroed hint has valid integer and pointer fields, `ai_addrlen` and null checks precede the unaligned sockaddr reads, and every successful non-null result reaches one `freeaddrinfo` (`dash-p2p/src/lookup.rs:20-57`). The function uses no static storage; glibc `getaddrinfo` is MT-safe. The error path has no owned result to free. No unsafe finding.
- Rerun of the r1 schedules: `-whitebind=127.1:9999` parses as `127.0.0.1:9999`, `-whitelist=11.1` as `11.0.0.1/32`, and `setban 11.1 add` creates that address row. The dedicated tests in `lookup.rs`, `permissions.rs` and `dashd_inbound_policy.rs` passed; a local glibc `getaddrinfo(AI_NUMERICHOST)` probe returned the same forms and returned scope ID 1 for `fe80::1%lo`.
- The new `qfcommit` test records the canonical inventory hash and verifies the wire, trailing-byte and canonical replies, then a second unrequested copy (`dashd-p2p/tests/sim_m2.rs:355-413`). Core checks `SerializeHash(qc)` after decoding (`src/llmq/blockprocessor.cpp:106-119`). I ran `mutants.py` on M4, M5a and M5b.
