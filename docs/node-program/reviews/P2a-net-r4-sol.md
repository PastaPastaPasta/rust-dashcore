## Finding

### R4-M1 — major: the generator retires 70222 peers that Core keeps, and the strict test does not detect that loss of live address-path coverage

**Both sides:** `node-l1/src/p2p_addr.rs:739-756` produces protocol version 70222 with `SendAddrV2::AfterVerack`; `:649-651` unconditionally sets `gone` after sending it. `Builder::seed` then skips the peer (`:544-563`), and all later message selection uses only `live()` peers (`:834-847`). Core v24.0.0-rc.3 `src/net_processing.cpp:4292-4304` checks `GetCommonVersion() < ADDRV2_PROTO_VERSION` **before** checking `fSuccessfullyConnected`; below the threshold it returns without disconnecting. Core `src/version.h:25-26` sets that threshold to 70223. The scenario is in the requested range: the changed seeder and stricter test inherit the existing unconditional end rule.

**Reproduction:** I temporarily decoded the delivered `version` payload in `node-l1/tests/p2p_addr.rs::core_run` and printed Core's outcome after each 70222 late-`sendaddrv2` pass, then restored the file. The 64 deterministic inputs per target contain **nine** such peers (2 `addr`, 2 `addrv2`, 5 `getaddr`); every reported outcome had `removed=false, disconnect=false`. The unmodified `scripts_reach_core_address_paths` still passes. Its `end_reason` accepts any post-`verack` `sendaddrv2` as an expected end (`node-l1/tests/p2p_addr.rs:83-94`), and the loop checks only that Core's actual ends can be explained (`:187-195`); it never checks that the generator has not prematurely retired a peer. One affected `getaddr` peer is index 1, the intended manual seeder (`node-l1/src/p2p_addr.rs:721-725`), so the fallback can seed from an inbound peer even though the manual peer remains live in Core.

**Impact:** This does not recreate the round-3 deliveries to already-ended peers. It silently removes live peers and some seeding/address work from the differential domain, contrary to D25's “live seeder” and the strict test's coverage claim. **Fix:** make `AfterVerack` end the peer only at common version >=70223; retain 70222 peers for seeding and later messages. Have the Core-only test compare expected live/end state after each pass, including peers Core keeps, rather than classifying only observed removals. Add a deterministic 70222 late-`sendaddrv2` case, including a manual seeder, to the gate.
