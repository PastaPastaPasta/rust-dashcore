1. **MINOR — Site 13 can taint an order-insensitive off-chain sibling walk.** `src/validation.cpp:4174-4175`. Two siblings of a locked block at a level below the fork point can both be off the active chain. If no eligible block in the re-add scan is tied with the active tip at site 8, `MarkConflictingBlock` marks each independently, emits the same tip events for each, and leaves the same final state in either order; site 13 still taints the step. This can cut off later comparison in fan-out ChainLock programs. **Fix:** retain the unconditional trigger when a sibling is active, and otherwise trigger only when the walk can make a site-8 address tie or another reported order-dependent effect. Add a negative regression with two off-chain siblings below the fork point and no site-8 tie.

2. **MINOR — Site 14 taints a prune even when the eviction boundary has no timestamp tie.** `src/chainlock/handler.cpp:148`. `unordered_limitedmap::prune()` uses `nth_element` by insert time. Add a unique-time negative regression if the trigger is narrowed.
