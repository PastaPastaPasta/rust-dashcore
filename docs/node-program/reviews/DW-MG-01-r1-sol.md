# MG-01 independent review — cbbcea1e

Scope: `8276bf62..cbbcea1e` in `dw/mg-01-salvage`. I treated MG-01 as a crate and vault delivery with no application facade yet. I compared the governance vote path with Dash Core v24's `vote.cpp` and `object.cpp`, and checked the ProTx oracle cases and vault call sites. The main ProRegTx encode/sign and internal-collateral resolution paths agree with the included dashd vectors; `add_vote` checks the voting key, future-time bound, and vote ordering once the parent object is present. The findings below concern the guard's ability to enforce D16/D20 and code that MG-02/MG-03 will consume.

## Findings

1. **Major — The operator-signing exception covers production code.** `rust/crates/dw-protx/tests/no_operator_signing.rs:78-87,292-303`; `rust/crates/dw-coinjoin/src/bls.rs:40-63`. The scan truncates *all* of `bls.rs` from `pub mod testing` onward. That module is public in non-test builds and exposes a BLS secret wrapper with `sign`. A production helper added after the module can call that wrapper, then be called from wallet code without any forbidden token or disallowed type at the call site. In a detached scratch worktree I appended `pub fn sign_any(seed: &[u8], digest: &[u8; 32]) -> Vec<u8> { testing::OperatorKey::from_seed(seed).sign(digest) }`; all three `no_operator_signing` tests and `cargo clippy -p dw-coinjoin --lib -- -D warnings` still passed. A later caller could use it to sign a service/revocation digest and place the signature in a decoded payload through the known enum-variant gap. **Fix:** keep the test operator signer out of production builds (a test-only fixture or explicit test feature), and constrain the exception to the exact test module so appended or re-exported production items are checked.

2. **Major — Masternode-key operations can cross a vault lock with a cached data key.** `rust/crates/dw-vault/src/vault/masternode.rs:112-119,144-146,173-185`. `store_masternode_key` and `delete_masternode_keys` copy the full-scope DEK before taking `writer` and the exclusive operation gate. If `lock()` completes in that interval, the call later acquires the gate and commits using the old key, changing a locked vault after the lock returned. `masternode_key_roles` similarly computes and returns sensitive role associations after a concurrent lock because it never enters the gate or checks the epoch before release. The existing `commit_records_under` only verifies the file and does not recheck lock state. **Fix:** after taking `writer` and draining operations, re-read and validate the current full-scope key/epoch before computing IDs or committing; run role listing through the gated `with_loaded_key` pattern so lock waits for it and a stale result is refused. Add a deterministic lock-race test for these APIs.

3. **Minor — Invalid duplicate orphan votes can exhaust the orphan queue.** `rust/crates/dw-governance/src/store.rs:187-202`. For an unknown parent, `add_vote` queues a vote before checking whether its outpoint exists, its timestamp is acceptable, or its signature matches the voting key; orphan hashes are not deduplicated. One peer can repeat the same malformed funding vote 50,000 times and fill `MAX_ORPHAN_VOTES`. Legitimate votes arriving before their object are then discarded, and processing the eventual object repeats the signature work for every queued copy. Dash Core checks unknown-parent votes before storing them (`governance.cpp:820-835`). **Fix:** validate the known voting key, time and signature before orphan insertion, track queued vote hashes, and bound unrequested votes per peer when MG-02 wires the transport.

## Evidence and limits

- The requested branch was clean at `cbbcea1e`. I made no edits to it.
- In the detached scratch worktree, the unmodified `no_operator_signing` test passed (3/3). After the production signing-helper mutation, the same test still passed (3/3) and Clippy accepted `dw-coinjoin` with warnings denied. This establishes a guard bypass, not a current UI or IPC call to that helper.
- I did not rerun the supplied 1,976 Rust tests, 653 Vitest tests, or Playwright gate. The supplied oracle and gate evidence covers those runs. The scratch mutation was isolated from the branch.
- `GovernanceStore::funded_height` currently trusts decoded triggers without object validation (`store.rs:276`); MG-01's design explicitly assigns object validation and the facade to MG-02. No displayed funded state exists in MG-01 itself. MG-02 must enforce that boundary before using this method.
