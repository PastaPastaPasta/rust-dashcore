Target: `node/p3-design` at `8a50d325d` (rev7), against Dash Core `v24.0.0-rc.3`. I read the common reviewer contract, Sol r5, the rev7 delta, D37–D42, DEC-229/230/233, and the relevant CH1-node and Core source. This is a design review: the new relay slot and stamped queue are not implemented, so no implementation test exists to run. D12 is outside scope.

## Finding

### F1 — Major — the `PreStart` to `Live` transition leaves a relay callback without a slot

Design: `P3-block-download.md:550-558,600-615,1578-1587,1621-1625`; `P3-notes.md:48` (D41). `relay_slot()` returns immediately in `PreStart`, with the stated consequence that its later push discards. But acquiring the slot and pushing are separate operations, and the first actor drain changes the mode to `Live` between them.

Concrete schedule: the signals thread enters `UpdatedBlockTip` and gets the immediate `PreStart` return, then is preempted. The actor's first drain switches to `Live`, and its first pass processes a peer's `VERACK`, making that peer fully connected. The signals callback resumes, sets the IBD flag, reads that peer as a recipient and reads the current stamp. Core's queued callback may likewise run its recipient scan after `VERACK` (`net_processing.cpp:2269-2307`). If the `PreStart` token makes `push` discard as specified, the live peer loses its announcement. This cannot be explained by placing the whole callback before `VERACK`: the port also sets the IBD flag only after `VERACK`, and Core sets that flag before its recipient scan. If `push` instead admits the entry in `Live`, the design must say how that no-reservation token is accounted for. The existing pre-start test checks work wholly before the first drain; it does not cover this crossing.

Fix: make `RelaySlot` an explicit token consumed by `push`, and reserve one slot even for a `PreStart` return without waiting. `push` should decide under the queue lock: discard and release the reservation while still `PreStart`, or consume it for a `Live` entry after the transition. `close` may discard either case. An alternative is an atomic `Live` reservation at push, with the single signals producer preventing an intervening relay push, but that exception needs to be specified. Add an S1 barrier test that pauses the callback after the `PreStart` slot return, runs the first drain and `VERACK`, then resumes it and checks the recipient's section 7 result.

## Narrow dispositions

- **Sol r5 F1, steady state:** closed. The slot is taken before the IBD flag, recipient scan and stamp read. The S thread holds no lock while parked (`signals.rs` dispatches outside its FIFO lock), and the current P2P paths have no actor-side signals `sync`. V's `limit_queue` uses `ServiceWait`, which serves R/M commands (`actor.rs:707-752`); an actor `Activated` wait drains signals, and an R/M-complete `ProcessHeaders` reply can finish before the actor's next drain. A full-lane send is serviced at a release point. V's in-hold waits must still satisfy A-1b (6), as the design requires. A fresh actor snapshot covers every previously queued relay stamp, and D39 takes a covered relay entry from behind an ineligible V entry. A batch retains its slot only until that entry is processed, so it cannot make the cap ineffective. **The DEC-233 acyclic-progress condition holds for the specified V/S/A wait paths.** F1 above concerns the mode transition, not that wait-for proof.
- **Core scheduler and shutdown:** delaying the whole callback after a `Live` slot wait is a valid queued-callback schedule; the IBD flag, recipients and stamp are read after the wait. A-12's order closes the queue with the actor before the signals thread's final flush, and `close` wakes a parked producer. Core unregisters PeerManager and stops connman before `FlushBackgroundCallbacks` (`init.cpp:346-360`).
- **Bounds:** relay entries are excluded from V's 1,024-entry/8 MiB checks and have their own 64-entry cap, including actor-held batches. Thus the parked-V residue is V entries alone. Each relay entry is `size_of::<Entry>() + 8P` bytes plus inline hashes; at default P = 125, roughly 1.3 KiB times 64 is roughly 83 KiB. `-maxconnections` does not constrain the slot count; A-9 still needs ND1's actual upper bound for P, including admitted extra connections. The single signals producer means the transition race does not by itself create a 65th entry; its problem is the specified discard of a callback whose body runs in `Live`.
- **Sol r5 F2:** closed. `PeerId` is `i64`; `Vec<PeerId>::into_boxed_slice()` gives a slice with an allocation layout for exactly its length, and D42 requires `retire` to rebuild it the same way. The proposed counting-allocator churn test checks the recorded recipient cost before and after retirement. The allocator's own size-class overhead is outside this logical allocation accounting.
- **D37–D40 rewrite:** the new rows correctly state the rev6 rules already accepted in r5: every eligible entry is taken in queue order, `NewPoWValidBlock` chooses recipients at application, `HeadersRelay` keeps callback-time recipients, merges require equal stamp and recipient list, and retirement removes finalized peers. No previously accepted rule changed. The stale 2Q/C/P bound is removed.
