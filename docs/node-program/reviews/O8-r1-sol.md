# O8 StateDigest v1 — independent review, round 1

2026-10-12. Reviewed the O8 spec at rdc `8e6e8453d` and Core `v24.0.0-rc.3..0a36fab32c` in detached worktrees. Mutations and build products stayed under private `/work/scratch/o8-sol-r1/`; the implementer worktrees were not edited.

## Findings

1. **High — a missing semantic MN-list hash makes the extractor suppress its own cross-checks.** `conformance/src/digest/extract.rs:433-458` treats `s.mnl != null` as proof that DIP3 is active, and `:268-284` uses that conclusion to decide whether to call the MN/quorum and canonical-list RPCs. I removed Core's `TapNewList` call at `src/validation.cpp:2721` and reindexed the same 221-block `feature_governance/node0` chain. Existing vectors exposed 219 `mnl` mismatches, but a fresh extraction ran twice byte-identically, omitted 885 formerly present sparse records (including all nine `canonical_mnlist` records), reported zero DEC-177 samples, and `store-vectors.sh` accepted it. This can turn a broken Core hook into apparently valid new goldens. **Fix:** derive era from the frozen chain's consensus parameters or independent RPC data; reject null/missing in-era `mnl`, `qc`, and `cp`, and require the expected sparse coverage before storing.

2. **High — copied Core header fields are not independently checked before becoming goldens.** `conformance/src/digest/extract.rs:714-741` checks block identity, height, and previous hash, then copies the rest of `s` into the golden. A Core encoder mutant swapping `nBits` and `nNonce` at `src/statedigest.cpp:166-169` produced 442 semantic mismatches against the existing 221-block vector. The new extraction was nevertheless byte-reproducible, all nine DEC-177 checks still matched, and `store-vectors.sh` accepted it. `blocks.dat` and the frozen node have the correct header values. **Fix:** verify `prev`, `ver`, `mrkl`, `time`, `bits`, `nonce`, `work`, and `ntx` against the raw block/RPC chain before writing `C`; do not use reproducibility as evidence of correctness.

3. **High — storage checks do not bind the set of nodes or digest bytes to extraction.** `contrib/node/statedigest/store-vectors.sh:16-49` enumerates only directories already under `rec/node*`, hashes only `golden.jsonl`, and runs `statedigest-stats`, which checks grammar and record kinds but not coverage or the `A` join. A scratch fixture with a missing node directory stored successfully. Replacing a previously extracted digest with its single `H` line also stored successfully, alongside the unchanged full golden. A present but unextracted node does fail, as intended. **Fix:** record and check an expected test/node manifest, bind `extract.json` to the exact digest and decisions hashes, and verify tip-connect suffix, provenance counts, and `A` joins before replacing the destination.

4. **Medium — two effects can be recorded before the effect completes.** `src/validation.cpp:2861-2862` emits `is_rm` before `RemoveConflictingISLockByTx`, whose implementation at `src/evo/chainhelper.cpp:93-99` can return `false` after a second lock lookup. Concurrent InstantSend changes can make the emitted hash differ from the lock actually removed or record a no-op. `src/llmq/snapshot.cpp:324-329` emits `snap` before the database write, whose result is ignored. These are static findings; I did not force the race or I/O failure. **Fix:** tap after a confirmed removal/write and use the identity returned by the operation; handle a failed snapshot write explicitly.

5. **Medium — post-connect record construction is outside the exception guard.** `src/validation.cpp:2491-2515` catches throws from `ConnectBlockImpl`, but `attempt.Connected` runs after that catch. It allocates, hashes, queries versionbits, and builds the line (`src/statedigest.cpp:144-170`). An exception there leaves a successfully connected block without its specified `C`/`A` or an `R`, and does not set the recording failure flag. The credit-pool call has a `std::exception` catch, but that does not cover `Connected` or non-standard exceptions. This is a path analysis, not a fault-injection result. **Fix:** guard all post-body record construction; after a successful connect, mark recording failed and abort on a recorder exception.

6. **Low — the literal flags-off no-allocation claim is stronger than the code.** `src/statedigest.cpp:102-114` allocates a run string and `Writer` during init even when both flags are unset. `DisconnectBlock` always constructs a scope and passes through its wrapper (`src/validation.cpp:2283-2294`), although its taps return without serialization. The measured gate still passes. **Fix:** short-circuit init when neither flag is set and mirror ConnectBlock's direct flags-off path for disconnects if a zero-work claim is required.

## Validation and limits

The Core build tree was reflinked from the implementer's build, reconfigured to its private path, and built with `nice -n 10 make -j12`. Rust builds used private `TMPDIR`, `CARGO_TARGET_DIR`, and `CARGO_BUILD_JOBS=12`. All probes used regtest or stored regtest bytes. I did not rerun the full callgrind gate, all Core FTs, a parallel-worker benchmark, or fault-inject the conditional effect/exception paths. No live mainnet or testnet oracle was queried. Source files in the detached review worktrees were restored after mutation; no commit, push, or GitHub action was made.
