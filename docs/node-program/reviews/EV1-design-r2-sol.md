## New findings from the changed sections

### Minor N1 — mempool has no `check_sigs=false` binding

`docs/node-program/designs/EV1-specialtx.md:814,888` says the false-flag MNHF/AU vectors run on both block and mempool bindings. At the pin, `src/validation.cpp:805-808` hard-codes `/*check_sigs=*/true` in `CheckSpecialTxForMempool`; no mempool caller can supply false. Keep the false-flag vectors on the block/model context (where Core's type-7/9 routines ignore the flag), and test the mempool binding separately with its fixed true value.

### Minor N2 — D14's quorum-count example is internally inconsistent

`docs/node-program/designs/EV1-specialtx.md:813,912` describes 33 mined Platform quorums, then asks for a signature from a 34th-oldest quorum. Core requests 33 quorums (`src/evo/assetlocktx.cpp:121-129`) and `llmq_60_75` has 32 active (`src/llmq/params.h:380-395`), so a 34th-oldest mined quorum requires at least 34 mined/retained quorums. Adjust the fixture count or use an explicitly retained older known quorum.
