# P3 block-download design, Sol round 7

Target: `node/p3-design` at `8b6f156f0` (rev8), against Dash Core `v24.0.0-rc.3`. Scope is the rev7-to-rev8 D43 relay-slot change and the four questions in the round-7 brief. I read the common reviewer contract, my r6 review, the rev8 delta, and Core's `UpdatedBlockTip` and section 7. P3 is still a design, so there is no implementation test to run. D12 was not reviewed.

## Findings

### F1 — Minor — the sketched public API does not bind a token to its queue

`P3-block-download.md:609-613,622-624` shows `SignalQueue::push_relay(&self, slot: RelaySlot<'_>, ...)`. The token records its queue, but the signature allows a token from queue A to be passed to queue B. If B already has 64 relay entries, `B.push_relay(token_from_A, ...)` can add a 65th entry without a B reservation unless the implementation checks ownership. A's reservation would then be released or transferred incorrectly. This does not occur in the specified one-queue ND1 path, but the claimed hard cap should be an invariant of this public operation. Specify that `push_relay` checks `std::ptr::eq(self, slot.queue)` before taking the leaf lock, or put the push on `RelaySlot` so it can only reach its own queue. On every consuming path, disarm the token before its `Drop` can release the same reservation again; transfer the counted reservation to a new entry exactly once.

### F2 — Minor — older cap and PreStart wording conflicts with D43

`P3-block-download.md:597,679` still describes the cap or wait in terms of queued entries; `P3-notes.md:48` still says a `PreStart` return's later push discards. A `PreStart` token can now be outstanding after the first drain, and its later push must be admitted in `Live`. Update these older sentences to count queued entries, actor-held entries **and** reservations, and say D43 governs the push-time mode decision. The current D43 text itself is clear, so this is a documentation consistency issue rather than a renewed F1 failure.

## Narrow checks

- **r6 F1 closes.** The signals thread obtains a counted reservation in `PreStart` and pauses. The first drain changes the mode to `Live`; the actor processes `VERACK`; the callback then sets the IBD flag, reads the newly connected peer and the published stamp, and calls `push_relay`. Its leaf-lock decision sees `Live`, retaining the reservation for the new entry (or releasing it on a merge). A later eligible drain applies the entry and section 7 can announce the tip. Core's queued `UpdatedBlockTip` can scan the peer after `VERACK` (`net_processing.cpp:2269-2304` at the v24 tag). Its IBD flag update likewise occurs before that scan, so the callback cannot be placed wholly before `VERACK` to justify r6's discard.
- **Cap and lifetime.** Let the count be queued entries plus actor-held entries plus outstanding reservations. Acquisition in `Live` occurs only below 64; the single signals thread can hold at most one reservation in `PreStart`, when there are no relay entries. A merge, `PreStart` discard, or closed discard releases once; a new entry takes over the reservation until that entry is processed. A callback early return or unwinding panic drops its local token and releases it. A token held indefinitely remains counted, so it cannot create a 65th entry; deliberately forgetting tokens could exhaust capacity and stall the producer, but no specified callback path does that. `close` makes subsequent acquisitions unreserved, wakes a parked producer, and causes an outstanding token's later push to discard and release; a token held during close remains counted until then or until drop.
- **Previously accepted rules.** D43 adds no wait: the only wait remains `relay_slot` in `Live`, before the callback body and without a held lock. `push_relay` takes only the queue leaf lock; its decision reads the mode and DEC-230's O(1) counters, with no V or actor wait while locked. Thus the DEC-233 acyclic-progress proof remains intact. `close` still precedes the signals thread's final flush under A-12, and the D39 drain still takes every eligible relay entry, including one behind a later-stamped V entry.
- **S1 barrier.** The specified pause after the `PreStart` return, followed by the first drain and `VERACK`, reaches exactly the r6 failure schedule. With an out-of-IBD tip that the peer does not yet know, Core's raw-vector model gives a nonempty section-7 announcement for each header preference; removing D43 makes the r6 push discard and the test fail. The no-drain, close, and IBD-return variants also exercise the three release paths. The test should assert the actual entry count and reservation count, not only the counter's value, to catch an accidental double release.

VERDICT: ACCEPT-WITH-CHANGES
