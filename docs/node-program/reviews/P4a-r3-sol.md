# P4a inbound policy review, round 3 (Sol)

**Verdict: ACCEPT WITH NIT.** The r2 P2 scoped IPv6 bind/dial defect is fixed at `a9cd2907e`. I reviewed `4c8acd8dc..a9cd2907e` in a detached worktree against Dash Core v24.0.0-rc.3 (`0364ed626e`). No branch edits, commit, or push were made.

## Finding

1. **P3, pre-existing and not on the node's numeric lookup path — the public `SystemResolver::lookup_host` still rejects interface-name scopes.** `dashd-net/src/resolver.rs:91-99,107-122` calls its own numeric parser, which accepts only digits after `%`, then returns no result when `allow_lookup` is false. On this host, `SystemResolver::default().lookup_host("fe80::1%lo", 1, false)` returns `[]` (the test explicitly asserts this at `dashd-net/tests/runtime.rs:524`), whereas Core's `LookupHost`/`WrappedGetAddrInfo` returns `fe80::1` with `sin6_scope_id=if_nametoindex("lo")`. This difference predates D23 and is tracked by BL-205. Normal P2P numeric lookup goes through `dash-p2p/src/seeds.rs:60-75` first; its platform `getaddrinfo` recognizes `%lo` and bypasses `SystemResolver`, so this does not reopen the r2 bind/dial defect. A direct caller of the exported helper would still see the difference.

## Checks

- **Scope ingress and socket egress:** Unix numeric lookup copies `sin6_scope_id` from `getaddrinfo` (`dash-p2p/src/lookup.rs:20-62`), matching Core `netbase.cpp:44-95`. `Service::from_socket_addr` keeps an accepted peer, local bind, or connected socket's IPv6 scope (`dash-p2p/src/netaddr.rs:795-802`; `dashd-net/src/binds.rs:220-225`; `dash-p2p/src/netcore.rs:958`), matching Core's `CService(sockaddr_in6)`. `SystemResolver` keeps numeric `%N` and DNS answer scopes (`dashd-net/src/resolver.rs:89-122`). `maybe_flip_to_cjdns` retains the field as Core's network flip does. `Service::to_socket_addr` sets it for IPv6 and CJDNS (`dash-p2p/src/netaddr.rs:781-790`), then `bind_listen_port` passes that address to `socket2::Socket::bind` (`dashd-net/src/binds.rs:74-100`) and `NetCore::open` passes it to `TcpStream::connect` (`dash-p2p/src/netcore.rs:927-932`). For `-whitebind=[fe80::1234%lo]:19999` or `-connect=[fe80::1234%lo]:19999`, both paths therefore submit the interface index rather than zero. I found no other P2P construction of a `SocketAddrV6` on either path. The separate RPC bind is BL-208 and outside this review.
- **Identity, keys, and wire:** `NetAddr` equality, ordering, and hash use only network and bytes (`dash-p2p/src/netaddr.rs:80-120`), as Core `netaddress.cpp:610-617` and `CServiceHash` do. Derived `Service`, `Address`, and `SubNet` identity therefore ignores scope consistently. The AddrMan `HashMap<Service, i32>`, scheduler `HashSet<Service>`, local address `BTreeMap<NetAddr>`, and ban `BTreeMap<SubNet, BanEntry>` cannot create two keys for the same address and port or subnet solely from two scopes. `SubNet::matches` compares masked bytes; `Service::key` uses address bytes and port. V1 and ADDRv2 encodings omit scope and their decoders start at zero (`dash-p2p/src/netaddr.rs:177-257,260-289,805-811`; `dash-p2p/src/addrman/ser.rs:140-202`), matching Core `netaddress.h:442` and `CService::GetKey`.
- **Text and ban reload:** `Display` adds `%N` only to IPv6 when `N != 0`; scope zero has no suffix, CJDNS prints the IPv6 bytes without a suffix, and onion has no scope text (`dash-p2p/src/netaddr.rs:674-693`), matching Core `CNetAddr::ToStringAddr`/`IPv6ToString` (`netaddress.cpp:520-606`). An IPv4-mapped socket or numeric IPv6 input is normalized to IPv4 by `from_legacy_ipv6`, as Core's `SetLegacyIPv6` does, so its scope is not printed. `CSubNet::ToString` parity follows from its address text and CIDR suffix (`dash-p2p/src/netaddr.rs:935-942`; Core `netaddress.cpp:1052-1082`). `banlist.json` writes and reloads `fe80::1%7/128` with scope 7; an unscoped `fe80::1/128` reloads with scope zero and has the same match set. The scoped/unscoped `setban` and `listbanned` tests exercise the same key and text behavior.
- **Safety note:** the DEC-249 test-only `if_nametoindex(c"lo".as_ptr())` call (`dash-p2p/src/lookup.rs:208-211`) passes a static NUL-terminated C string that remains valid for the call; libc does not retain it. Its `SAFETY` note is accurate. This is the one test-only exception; the production `getaddrinfo` unsafe function remains the separate DEC-246 exception.
