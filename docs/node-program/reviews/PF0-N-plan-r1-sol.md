# PF0-N design plan review — round 1 (Sol)

Scope: `/work/scratch/pf0-n/plan.md` and its `proto/` launcher, against the read-only integration checkout at `eefe072b2`. All experiments and temporary files are under `/work/scratch/pf0-n-r1-sol` (0700). I did not run a gate or anchor, or use `/work/perfgate`, `/work/bench`, or `/work/chains`.

## Findings

**Major (confirmed existing F0) — perf output is writable by measured bench code.** `plan.md:28-32`; `contrib/node/perfgate/perfgate/measure.py:134-168`; `contrib/node/perfgate/perfgate/node.py:62-78`. `perf stat -o` leaves its output fd open across bwrap, so a bench can reopen `/proc/self/fd/3` and append a forged CSV event. In my scratch reproduction the parser returned 7 while perf recorded 74,696,125 instructions. **Fix:** put a trusted close-fds exec shim between perf and every bench/node sandbox, keep any deliberately passed node pipe separate, and test the exact bwrap chain. The extra helper instructions also require finding 9’s anchor check.

1. **Blocker — a PR binary has an unwrapped execution path before preflight.** Plan §2/§7 (`plan.md:53-71,180-181`); `node-bench/nodebench/impls.py:76-85`; `node-bench/nodebench/workloads.py:340-352`; `contrib/node/perfgate/perfgate/node.py:112-124`. `cmd_workload` calls `impl.describe()`, whose `version()` runs the selected `rdashd -version` directly, before the proposed refusal preflight or `Node` wrapper. Today node-bench's outer sandbox makes its entire `NODE_BENCH_ROOT` writable. A PR binary executed for `-version` can therefore write outside its own disposable run directory (and, if that bind contains the master or baseline, corrupt those). The present fixture preparation also starts `Node` without a wrapper (`node-bench/nodebench/fixture.py:140-153`); the plan says prep will change, but does not cover `version()` or enumerate all binary invocations. **Fix:** make every PR-binary exec, including version, preflight, prep, measured runs, and any CLI probe, go through the same narrow launcher with a disposable writable directory. Bind no writable parent containing a master, baseline, other run, or other side into any PR process. Add a fake `rdashd` whose `-version` attempts those writes to the real end-to-end selftest.

2. **Major — the existing RPC workloads cannot cross the proposed network namespace.** Plan `plan.md:44,67,98-130`; `node-bench/nodebench/workloads.py:160-246`; `node-bench/nodebench/rpc.py:20-29`. `--unshare-all` gives each nested node a new network namespace. `node-bench` remains outside it and calls `127.0.0.1:<rpcport>` for readiness, stop, mempool, GBT, and RPC rows. Once an owner implements the missing flags, preflight will return OK but the real row will wait for RPC and then ERROR, blocking that legitimate merge. `startup-genesis` avoids RPC; the other rows do not. **Fix:** specify and test a communication topology now: for example, keep node and trusted RPC client in the *same* isolated outer network namespace while keeping the node's mount/PID restrictions, or provide a narrowly scoped trusted RPC proxy. Test a real localhost RPC round trip and rejection of host TCP and abstract sockets. The proposed `PENDING → NEW` path must run through this topology.

3. **Major — fd 5 can deadlock the prototype and defeat its stop path.** Plan `plan.md:58-65,74-79,157-166`; `proto/launch.c:90-97`. The outer launcher blocks reading the result pipe to EOF before draining the allocation pipe. A child that writes enough to fd 5 fills the pipe, cannot exit, and prevents `inner` from writing the result; SIGTERM does not break the outer read loop. The 64 KiB allocation buffer would also stop draining on overflow. I reproduced this with a scratch copy: 20,000 short writes to fd 5 hung beyond 7 seconds; SIGTERM did not finish it and the test had to SIGKILL the launcher's group. **Fix:** poll/drain result and allocation pipes concurrently, enforce a bounded record size/count/total, continue draining and discarding after an overflow while recording ERROR, and have an independent watchdog that kills the namespace on deadline. Assert a flooding child is gone after the test.

4. **Major — orphan cleanup has a PID-publication race.** Plan `plan.md:49,61-65`; `proto/launch.c:23-26,35-49`. If perf dies after `inner` installs `PR_SET_PDEATHSIG` but before it parses `child-pid`, `orphaned()` sees `target == 0` and does nothing. It does not save a pending kill, so after the PID arrives the sandbox may continue while the harness is gone. The `getppid()` check only covers the earlier race. **Fix:** record the orphan signal atomically, kill bwrap immediately when no namespace PID is known, and kill the namespace PID as soon as it is published. Fail closed on missing/malformed `--info-fd` data. Prefer `pidfd_open`/`pidfd_send_signal` after publication to avoid signaling a recycled PID. Add a repeated kill-at-launch test, including `setsid`/forked children.

5. **Major — disk, memory, and wall-time bounds are not established.** Plan `plan.md:33-37,204-205`; `proto/launch.c:35-103`; `node-bench/nodebench/cli.py:173-195`; `contrib/node/perfgate/perfgate/node.py:103-127`. The prototype sets no `RLIMIT_FSIZE`; even when added, 4 GiB is *per file*, so many smaller files can fill the shared XFS filesystem. `workload` does not expose `--limits`, and node-bench's current cgroup setup uses `sudo` under `/sys/fs/cgroup`, which cannot simply be invoked from the existing unprivileged outer bwrap. `node.run_once()` calls `subprocess.run()` without a timeout; the new `startup-genesis` readiness loop and preflight need explicit deadlines. **Fix:** put a trusted, aggregate disk and memory limit around the PR subtree (or document a tested host-safe alternative), enforce a gate-level wall deadline for every preflight/prep/measurement, kill the namespace on expiry, and test repeated small-file writes, OOM, and a node that never notifies. The free-space check at launch is not a runtime cap.

6. **Major — the master hash alone will not invalidate the existing anchor path.** Plan `plan.md:81-91,145`; `contrib/node/perfgate/perfgate/gate.py:278-288,356-385`; `contrib/node/perfgate/perfgate/cli.py:126-129`; `contrib/node/perfgate/perfgate/anchor.py:81-99`. `ANCHOR_COMPARABLE` is an explicit tuple; adding a master hash to a measurement's fingerprint does not make `drift_rows` compare it. The current `workload_inputs()` supplies `key`/`inputs` only for bench rows, so a changed node declaration, node-bench workload recipe, or rebuilt fixture can be compared to an old node anchor without a stale-anchor ERROR. **Fix:** give each node row an immutable inputs hash covering master manifest, fixture/content hashes, pinned dashd, workload recipe and relevant node-bench code; store and compare it in the anchor path (or add a node-specific comparable fingerprint field). Test mutation of each input after anchoring. Do not add the per-gate clone's path or gate ID to that hash.

7. **Minor — fd 5 is a self-report channel, not an additive-only one.** Plan `plan.md:19-27,76-79`; `contrib/node/perfgate/perfgate/node.py:92-100`. A child can open `/proc/self/fd/5` for reading and consume pipe records (I reproduced that with a scratch pipe), close it before its preload destructor, or write a negative JSON value. The current parser summed `1000` and `-900` into `100` allocation bytes. That is acceptable only under DEC-76's self-reportable-counter threat model, not the plan's assertion that forged lines “can only add.” **Fix:** describe the trust level accurately; reject negative, non-integer, overflowed, duplicate-key, oversized, and missing required fields. Do not present the pipe as authentication of the preload.

8. **Minor — `NEW` from PENDING is an explicit temporary blind spot.** Plan `plan.md:100-121,143-146`. The transition must waive the missing-anchor drift error, because there is no comparable base result. It also means the first implementation of a previously unsupported option can merge with an arbitrarily high memory cost, and PENDING/PENDING measures neither side. That is a policy choice, not the plan's categorical “nothing to hide.” **Fix:** record a DEC that limits the waiver to *base PENDING → head OK*, reports the three memory medians in the `NEW` row, requires a human review of that first measurement, and makes the next authoritative gate fail until the manager anchors the new row. Keep base OK → head PENDING as ERROR. Ensure preflight reports an unsupported option only when it was actually in the *original* argv, each retry removes exactly that option, and an exhaustion/ambiguous stderr remains ERROR.

9. **Minor — do not assume the F0 helper preserves existing anchors.** Plan `plan.md:28-32,175-176,202-203`. The helper runs inside `perf stat`, so its own loader/close/exec instructions enter every bench's `instructions_process`. In a scratch `true` calibration a minimal close-and-exec helper raised that count from 143,166 to 261,490; this is not an estimate for any particular bench, but it disproves a blanket “small constant under 2%” assumption. **Fix:** run the planned no-op comparison against the current anchor for all existing gated bench rows after inserting the helper; if any floor/drift decision changes, follow the documented justified re-anchor route. Keep the bench executable, its environment, CPU affinity and existing workload definitions identical.

## F0 and sandbox checks

- **F0 is real across bwrap.** `perf stat -o` left fd 3 open inside the bwrap child. A scratch child reopened `/proc/self/fd/3` and wrote a CSV record at offset 4095. The file contained a genuine `74,696,125` instructions row followed by `7,,instructions:u,…`; current `perfgate.node.parse_perf_csv()` returned `{'instructions': 7}` because the last event wins. This is a concrete existing `instructions_process` forgery. A trusted exec shim that closes all inherited fds ≥3 *after perf and before bwrap* stops this fd path for bench runs. For node runs it must close perf/strace file fds while deliberately constructing only the info pipe and fd-5 data pipe. It is complete for this inherited-file-descriptor route only if every PR process uses it, including the `-version` and prep paths in finding 1. Validate the child's `/proc/self/fd` set in both counter and syscall modes. `strace -f` did follow bwrap and the child exec in my scratch trace.
- **Filesystem and process visibility.** With `/work` hidden and only a probe executable plus its run directory bound back, an unrelated scratch decoy was invisible; a symlink from the run directory to it failed to read, and hard-linking the read-only executable into the writable run returned `EXDEV` (18). A host PID was absent from the private `/proc`, `kill(pid, 0)` returned `ESRCH` (3), and `/proc/<host-pid>/root` was absent. Attempted `umount /work` inside the namespace failed. These checks support the intended listed ledger/anchor/root read and write barriers, provided the final implementation binds back only exact trusted executables and the current run, and does not expose a parent gate directory.
- **Network/IPC.** Connections to a host TCP listener and host abstract AF_UNIX listener both returned `ECONNREFUSED` from a private net namespace. The `/run` and home mounts hide the standard pathname sockets; an arbitrary pathname Unix socket on any other visible read-only path could still be connected to, so the production layout should bind only what it needs and test the sockets relevant to this host. Private PID/IPC namespaces also prevent the tested host signal/ptrace target path. I did not find a route to the named protected roots through `/proc/self/fd`, hard links, symlinks, host `/proc`, or network sockets once unrelated fds and broad writable binds are excluded.
- **RLIMIT and lifecycle.** `RLIMIT_FSIZE` bounded each scratch file, but two 900-byte files were allowed under a 1024-byte limit (aggregate 1800 bytes), as expected. The current launcher’s FD-5 flood deadlocked; its orphan-before-PID race was found by inspection, not stress-reproduced. `--as-pid-1` and `--new-session` make signal forwarding and namespace-init semantics central; a normal `killpg` does not directly reach the node. Test clean SIGTERM, abort, daemonize/setsid, parent SIGKILL at every launch stage, and missing `--info-fd` data. `strace -f` observed the child through the namespace; the supplied `startup7*.log` supports the reported 7+7 noise, but I did not rerun rdashd or a full gate.

## Q1–Q9

- **Q1:** Yes. `node-startup-genesis` is a useful first live, fixture-free row; keep fixture/RPC `node-startup` PENDING until its full contract works.
- **Q2:** Yes, if the same documented fixed mocktime is applied to both rdashd and dashd and ND1 confirms notify follows successful init. The supplied 7+7 logs show little noise benefit at genesis; the value is state repeatability.
- **Q3:** Gate in-process `VmHWM` under DEC-76's explicitly self-reportable memory-signal policy, with external `wait4` as INFO and a discrepancy flag. At ~17.8 MiB, the current 2%/256 KiB RSS floor can detect a modest regression; the `wait4` prototype varies by >0.5 MiB and therefore takes the 4 MiB step floor, about 23% of this row. State that a forked child's RSS may not be represented by the node's own VmHWM and test the intended process-tree metric.
- **Q4:** Yes, write the PENDING/NEW DEC before lifting DEC-213, with the limited first-live waiver and post-merge anchoring obligation described above.
- **Q5:** Yes for genesis only. Build the fixture master independently of `/work/bench` before any fixture workload becomes live; fingerprint its exact contents and remeasure dashd against that fixture. The RPC topology in finding 2 must be ready before lifting those rows out of PENDING.
- **Q6:** Yes. An external `PERFGATE_NODE_BENCH` must make an advisory run non-authoritative. Also bind node workload recipe and master hashes into anchor comparison; a trusted *path* alone is not a stable *measurement*.
- **Q7:** Fix F0 in this task before running PR nodes. Do not promise “no re-anchor” until all existing bench rows are compared after the helper is inserted; use the existing justified re-anchor workflow if a row crosses its limit.
- **Q8:** Do not accept an uncapped PR node on the shared host as the final design. Put a trusted memory cgroup, aggregate writable-storage bound, and wall deadline around it; the existing `node-bench --limits` path is neither exposed on `workload` nor proven usable from the outer sandbox.
- **Q9:** ND1 should validate `rdashd` as namespace PID 1: its actual SIGTERM handler, default-signal behavior, notify child reaping, abort path, and shutdown exit status. The PF0 launcher must still kill and reap the namespace independently on timeout or parent death; `setsid` must not defeat that. Verify startupnotify is the right readiness boundary for the first row.

The proposed 15-run integration measurement and ten no-op advisory gates are a reasonable *minimum* false-FAIL check after these design gaps close; 7+7 prototype samples alone do not establish a production floor. Run base/head interleaved and examine raw ranges, escalation and rank outcomes for all three gated counters. Preserve existing PF0 bench rows and the old anchor until their measured helper delta is shown.

**Verdict: CHANGES-REQUIRED**
