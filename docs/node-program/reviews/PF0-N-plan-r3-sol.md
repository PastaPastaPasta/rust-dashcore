## New findings in rev2

### Major — D4’s required launch hardening is only recorded as a ruling, not an implementation requirement

This is the concrete N1 closure gap described in the table. §14 D4 is explicit that broker **and launch** must be non-dumpable before receiving protected material, but §3 names only the broker and §11 has no launch-specific negative test. Because `launch` is the process that inherits the sealed spec and is the helper immediately before the jailed exec, omitting this requirement leaves the settled trust boundary underspecified. Add `PR_SET_DUMPABLE=0` before spec/exe receipt in both launch personalities and assert from the node-bench view that launch `/proc` root/fd/exe/mem and ptrace access fail (or that launch is PID-hidden plus the required non-dumpability check).

### Major — `node_inputs` omits active node supervisor/parser sources

This is the N4 gap above, independently of the future implementation details. The plan’s promise that every trusted source is hashed is contradicted by its source table and by the current call graph (`node.py` → `measure.py`/`sandbox.py`/`run`). A change in `split_sched`, `collect`, bwrap command construction, safe result reads, or wrapper dispatch can alter a node row while the listed hash remains unchanged.

### Major — exact NEW-FROM-PENDING argv hashing is unstable without a deterministic PF0 argv contract

This is the N5 gap above. The branch’s `NodeConfig` defaults allocate random ports and the daemon argv contains per-run datadir paths. The plan must either fix those values/paths inside the PF0 namespace and state that contract, or define a canonical argv hash that removes only explicitly identified invocation-volatile fields while retaining all declaration and owner-relevant tokens.

### Minor — P11 does not validate the combined placement flags

The rev2 text claims `CLONE_INTO_CGROUP|CLONE_PIDFD`, but `/work/scratch/pf0-n/probe/rev2/into.c` sets only `CLONE_INTO_CGROUP`. Keep the P11 membership result, and add a probe/test using the exact production flag combination before treating pidfd-based cleanup as probed.

The three manager rulings are otherwise reflected: D18 leaves the global kernel fingerprint fields unchanged, D21 records PENDING anchor rows, and the D4 sibling-broker deviation is the approved architecture (subject to the launch hardening above).
