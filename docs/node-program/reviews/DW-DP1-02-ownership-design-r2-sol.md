## Required synchronization: D15

The pinned [§5.2b](/work/scratch/dp1-02-design-r2-sol/DP1-02-ownership-model-99d6c81.md:247) still says “the code alone keeps the row `Cancelled` … whatever later evidence reads.” That is false under its [§3.2 `row_of`](/work/scratch/dp1-02-design-r2-sol/DP1-02-ownership-model-99d6c81.md:109) and first-match standing table: an outstanding step wins before the failure-code arms. The original model deliberately reports these as notes, not safety failures. I independently reproduced all three classes:

1. **In-memory NotSent → Close → restart:** durable signed evidence reappears, making the coded row `Awaiting`.
2. **Clear → restart → own-lock adoption:** the row takes the returning signed lock and becomes `Funded` despite its cancel code.
3. **Wrong-holder closure → holder consumes → holder discarded:** the coded signer/heir becomes `row_of` again and reads `Awaiting`.

The original traces are in [model-check.log](/work/scratch/dp1-02-design-r2-sol/model-check.log:7), including the wrong-holder trace at line 40. They support the manager's diagnosis; they do not establish a new double-funding finding.

**D15 closes the rebound without dropping money evidence.** Compute the holder-or-signer candidate as before, then return no `row_of` if that candidate has either durable cancel code. Keep the signer, holder, signed records and tombstones as evidence; do not fall through to another candidate merely because this one is closed. The closed row then has no associated outstanding step, so the failure-code arm keeps it cancelled. A returning unspent Exact lock remains `Step(S)` and goes to permitted `Recovery`; consumed signed value settles in place. A record-only Exact step still has reconstruction/Repair as its exit. An Unknown step does not become resolved merely because its row closed.

Replace §3.2's `row_of` definition with:

> `row_of(S)`: choose `holder(S)`, otherwise `signer(S)`. If the chosen row is closed with `registration.funded_elsewhere` or `registration.funding_cancelled`, return none; otherwise return that row. Exact possession precedes draft id and heir. The exclusion does not remove any step or lock evidence.

Replace §5.2b's inaccurate sentence with:

> Once `Close` writes a cancel code, D15 excludes that row from `row_of(S)`, so later evidence cannot make its step reopen the row. The row takes no Free or Step lock. Consumed signed value settles in place; returning unspent signed value goes to Recovery under §5.1. An Awaiting row whose voided outpoint is cleared without a cancel code remains eligible for its own Step lock.

Add D15 to §13.1 and update the committed model's `Ledger.row_of`, closure invariant and mutation. The review-only [D15 overlay](/work/scratch/dp1-02-design-r2-sol/d15_check.py) applies precisely this candidate exclusion, asserts independently that a cancel-coded row is never `row_of`, and adds a mutation that removes the exclusion. It passed all ten scenarios, the original sixteen mutations, and the new mutation. All original closure-rebound notes disappeared. This is stronger evidence than only rewording the paragraph.

## Replaying OD-03, OD-04 and OD-05

**OD-03: the actual r7 consumed-lock fixture now has a terminal transition.** A is open with no outpoint/identity; S_A names durable T1; the library reports T1 Consumed and discovery reports `identity_for(T1)`. `owner` correctly excludes consumed value from unspent allocation, but §5.2a separately authorizes `Attach` to A. Before the write A is Awaiting and pending is 1. The single write records T1 and its existing identity, adopts discovery's authoritative key index j, clears the failure and sets IdentityRegistered. It settles S_A, pending becomes 0, and the run proceeds without `fund` or IdentityCreate. B receives no permission to take T1. When discovery has not reported the identity, A stays Awaiting/Network; it does not invent an association or fund again. If no eligible row remains, consumed value settles in place instead of creating a Recovery row or reviving a discarded Done row.

The [literal replays](/work/scratch/dp1-02-design-r2-sol/review_probes.py) passed those decision assertions. The exhaustive consumed-elsewhere scenario reaches Attach and in-place settlement. **Index j is checked on paper against §5.2a:** the Python model explicitly fixes the attached identity index to the row's index and cannot validate the different-index Rust write. Preserve §11.2 item 4's real regression with j different from A's old index.

**OD-04: Repair NotSent with an already-recorded outpoint releases correctly.** A records T1; tracking is lost; Repair's covering ChainLocked self-spend resolves S_A and retains T1 in `dead`. `live(A)` immediately becomes none, so raw appdb possession no longer makes A Funded. With no other outstanding step, row 8 gives Cancelled(funding_cancelled). One non-calling CAS clears the exact outpoint and writes the non-retryable failure, with the required backup re-arm. A is no longer committed; discard/start are allowed once no other hold blocks them. A fresh draft is required.

The exact-match controls hold: resolving T1 never clears a live substitute T2. If A records a voided T2 but still has its own outstanding T1, Awaiting wins; Close clears only T2 without a cancel code and A can still receive T1. D15 handles the separate case where a code was already written before a failed NotSent write was lost on restart: preserve the evidence and recover the money without reopening A.

**OD-05: the pre-marker actor/J window is covered.** After `enter_funding`, A can still read Unfunded before its marker exists, but `calling(A)` makes Free/Row permission false. A tap or Finish cannot insert foreign T2 into A while permit work is outstanding. If allocation ran first, the actor admission recheck sees the outpoint and does not start the call. Once exact T1 exists, Step/Row allows A to take it even while calling; Recovery is denied while A is its eligible open `row_of`. The flag lasts through post-call writes, whose fresh ledger must recognize tap/Finish's already-held own lock. No marker-level lock-order assumption is needed to bridge the gap.

## C4, C5 and Q8

**C4 is safe and removes the attribution cycle.** A flagged step with nonempty tombstones and no active signed lock has no surviving funding from that resolved attempt. PA-2 records every possible outgoing lock; resolution kills that attempt's lock; `StepCancelled` prevents a second call. Therefore P2b may derive a resolved status regardless of an unrelated unattributed or re-keyed row, and DP1-02 reads that result. Foreign unspent U is Free rather than permanently Contested and reaches attribution through Finish/Recovery/identity. Keep active `signed` separate from `dead`, retain the resolved marker's flag, and apply C4 only with that flag. The unflagged control remains Unknown. Q13 makes P2b's status, gates, events and PA-1 view agree; DP1-02 should not grow another independent override.

**C5 is safe with Q14's closure policy.** After a crash there is no running call, and a flagged marker with no signed record proves no lock escaped the durable-record gate. It reads NotSent while the standing marker still vetoes another permit. Closing A as Cancelled(funding_cancelled) resolves the consumer wedge: no money was paid, the row can be discarded, and a new draft uses a fresh index. It must not silently replace the stale marker or retry that step. Durable zero-signature NotSent that actually superseded its marker and has no tombstones remains H12's separate retry case.

**Q8 establishes the restore/legacy induction base without transferring value.** For a supported starting state where B′ records T1 signed by S_A and A′ is open at S_A's index, exact holder B′ is `row_of`; B′ keeps T1 and its one outpoint-derived identity. A′ closes as funded_elsewhere before it can fund or move index, even before Close persists the code. A consumed T1 is not donated back to A′ or used for IdentityCreate again. Once closure is written, D15 prevents A′ from becoming eligible merely because B′ later disappears. A signer holding separate live value remains Funded and keeps that value. This is the approved terminal historical association, not permission for new contrary attachments.

## Model fidelity, bounds and liveness

I inspected the decision sites and transitions, not just the success banner:

- **§3 evidence/predicates:** `claim` implements None/Exact/Unknown, flag-dependent absence, C4 and C5; `live` reads tombstones; holder precedes signer/heir; consumed settlement preserves an open row's need for Attach and otherwise settles in place. The pinned `row_of` matches the pinned pre-D15 document, so its original pass does **not** validate D15.
- **§3.3–§5:** standing uses the specified precedence; Free permission checks both Unfunded and not calling; Step permission checks the open exact recipient; Recovery cannot take an open caller's Step value. Reconcile separates consumed Attach from exact clear/closure. Pending counts unheld outstanding steps and conservatively counts Unknown/Contested twice. The held path is independently checked.
- **§6 events:** call admission precedes marking, post-call retains calling, tap/run/Finish use permission, Finish reconciles before allocating, restore re-numbers rows while retaining evidence, Repair resolves exact recorded conflicts, and both index functions account for other drafts' retained steps. Proof/reconstruction does not turn synthetic index 0 into trusted provenance.
- **Mutation sites are real decisions.** The eight new mutations target calling-Free permission, Recovery of an open caller's lock, Attach, Close, exact clearing, holder transfer, next-index retention and C4 derivation. The eight retained mutations target step enumeration, Unknown release, discard, held pending, orphan Recovery, heir association, Contested permission and Awaiting-Free permission. Independent transition checks use lock/intent truth or the unmutated reference ledger. The liveness mutations fail through inability to reach the goal, not an expected-failure whitelist. ## Every outpoint-writing route

A pinned-source search confirms the production writer categories: `record_lock` before/after funding, tap/Finish's `attach_lock`, appdb `adopt_registration_lock`, and [restore/import at rows.rs:133](/work/scratch/dp1-02-design-sol/dp1/rust/crates/dw-appdb/src/rows.rs:133). §5.2a adds the new consumed-value writer; §5.2b supplies the exact clearing writer.

All new unspent attachments must read a fresh ledger and pass §5.1 in the same actor job as the owner/CAS write. Successful `fund` return alone is insufficient; already-held own evidence must be recognized; an unexpected Ok outpoint is not adopted. Appdb's unique outpoint and CAS are writer safeguards, not ownership authorities. Consumed Attach requires exact `identity_for(outpoint)` discovery and never creates another identity. Clear requires that recorded txid itself in `dead`, not merely another tombstone of the same signer.

**Restore is deliberately different:** `import_wallet_rows` inserts registration columns directly and does not call `may_take`. §5.2c must therefore run before those rows drive registration decisions. A dead txid becomes non-live and clears; a signed txid keeps its unique existing holder and closes the open contrary signer; an unsigned historical record remains the only claim. Retained steps block fresh funding at their indexes even when the original ids are gone. Tombstones surviving `erase_wallet` are essential: without them a restored pre-closure T1 would become Funded indefinitely. With Q8, D15, those retention rules and the existing canonical/unique-outpoint constraints, I found no uncovered production route that invalidates the induction base.

No missing backend, false/no-op insert, failed attribution or failed journal write counts as success. Prove no other library Built-lock broadcaster bypasses this boundary. Retain the real published-Built/blocked-record/parallel-resume regression with zero broadcasts, restart controls, and successful-send controls. 3. **Schema 6 and OD-02:** mark the guarantee when each new marker is created; migrate older markers as unflagged. Database schema alone cannot bless historical attempts. Only flagged recordlessness with no running call supports absence-based NotSent; unflagged recordlessness stays Unknown. DEC-191's same-release gate is mandatory; no shipped pre-6 marker population is assumed supported by automatic release.
4. **PA-3 retention:** dead txids and their resolved marker flag survive supersede, reopen, compaction, `erase_wallet`, re-add and backup restore. Keep active and dead attempts distinct. 5. **StepCancelled/F7/H12:** refuse tombstoned steps; continue refusing standing C5 markers; keep the step bound to its key, including disguised Resumable permits. 7. **O-1:** enforce the one-independent-lock-per-call premise at the signer/permit boundary, with idempotent identical retries and refusal of another transaction. Test the real same-input payment refusal followed by successful Repair; retain the external same-seed spender residual explicitly.

Preserve exact, nonempty, actual-input conflict coverage and ChainLock finality as NotSent authority; legacy/empty records and chain-scan absence do not supply it. A Repair-resolution wakeup remains optional for prompt reconciliation; a later run/Finish can apply it. DP1-02 itself owes D15, the common ledger routing, atomic Attach/Close, backup re-arm, the new failure/wait contract, orphan entries and the §11.2 Rust regressions.
