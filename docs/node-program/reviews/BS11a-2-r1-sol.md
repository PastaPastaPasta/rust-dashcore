# BS11a-2 Sol r1 crypto/consensus review

**Verdict: ACCEPT WITH NITS.** I found no pinned-path BLS result or call-log mismatch. The following are bounded correctness and assurance gaps.

1. **Minor — D26's entry check is bypassed for a null script.** Core `src/test/oracle/oracle.cpp:2854-2855,2865-2874`: `oracle_bls_exec(nullptr, nonzero_len, ...)` returns `ORACLE_E_ARG` before reading and clearing an already-set thread-local relic code. A later valid call then fails on that stale code, contrary to D26's “a bls_exec call that starts with relic's code set” contract. Rust's slice binding does not make this call, so this is a C ABI edge case, not an observed consensus divergence. **Fix:** run the stale-code check before the null-script return (while holding the existing process-state mutex), and add a test-only way to seed the code before entry so D26 is tested directly.

2. **Minor — the throw-site reachability check has an unguarded indirect-call assumption.** rdc `contrib/node/oracle-relic/throwsites.py:74-76,295-311` adds only named disassembly targets/relocations and same-file functions named in source bodies. The pinned `ep_map_from_field` and `ep2_map_from_field` do call through function pointers; their two map targets are named in those same bodies, so I found no omitted site at this pin. A future callback or pointer table whose target is not named there could silently make a throwing function look unreachable. `build-oracle.sh:309` also preprocesses clang's archive with gcc. **Fix:** enumerate and fail on unaudited indirect calls from reachable functions, with explicit target edges for the pinned map dispatches; check the flavor's preprocessed throw-bearing lines or document a verified compiler equivalence on each pin move. The present 187/179 counts remain credible, but the script alone is not a completeness proof for a changed pin.

3. **Nit — state the log comparison precondition at the ABI boundary.** Core `src/test/oracle/oracle.h:841-849` describes the log without its process-history condition; base-sdk `contrib/vectors/bls_oracle/gen.py:569-584` warms the legacy map once because its two `std::call_once` constants add two `bn_make`/`bn_read_str` pairs on first use. The committed corpus is reproducible after that warm-up, but comparing its raw log to a first-use call in another process gives a false difference. **Fix:** document the exact warm-up and “same warmed process” comparison rule in the ABI/provenance text; keep comparing codes and outputs independently of log history. D30's rule is sufficient for the known pinned initializers when consumers actually follow it.

4. **Nit — distinguish wrapper observations from direct relic probes.** base-sdk `contrib/vectors/bls_oracle/gen.py:596-642` records P2's `(0,0)` multiplication and P5's rejected verify with pairing calls, but it does not expose `fp_inv(0)` or `pp_exp_k12(0)` directly. Thus P1 and P4 are inferred from those wrapper paths and the original raw-relic probe, not independently proved by `relic.json5`. **Fix:** label those rows as wrapper consequences and retain the raw probe evidence in provenance. The G1/G2 off-subgroup add, negate, multiply, infinity-shape and legacy/basic verify seeds are useful for BS11a-3; BS11b's aggregate, threshold and DH coverage still depends on the design's later differential scripts, not these five probes alone.

5. **Nit — update the accepted design's throw table.** `rust-dashcore@dc4faa03f:docs/node-program/designs/BS11a-legacy-bls.md:223-239` still says 913/191 and omits `md_xmd.c:48,68` and `relic_tmpl_map.h:231,310`. rdc `contrib/node/oracle-relic/throwsites.tsv:60-64` classifies the two XMD sites as fixed precondition/length and the two map-template sites as unreachable arithmetic. **Fix:** amend the design table to the archive-derived 870 total, 187 gcc and 179 clang reachable relic sites, and add those four rows. They do not add a demonstrated normal-path error at this pin, but leaving them out makes the stated static proof misleading.
