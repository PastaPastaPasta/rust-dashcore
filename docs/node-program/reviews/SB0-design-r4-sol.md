## New finding

### R4-M1 — Initial coverage has no valid rule for a short or pre-quorum genesis chain

**Severity:** major. **Refs:** §4.3.1, `docs/node-program/designs/SB0-shared-base.md:574`, `:580`, `:582`, `:585`, `:592`, `:594`; §5.2.1 `:800`, `:825`; SB11 `:1367`, SB15 `:1371`.

The horizon is finite, but the **mandatory initial-coverage targets are not clipped to the chain's valid domain**. Step 2 requires authenticated sets at `tip − 8` and `tip − H_keep`, applies steps 1–4 to both, and says a target below the candidate is uncovered. There is no empty/young-chain branch before `Established`.

**Concrete failure:** start an SPV client against an ordinary fresh regtest chain whose peer tip is **20**. The anchor is genesis and `H_keep = 56`, so initial coverage requests the oldest set at **−36**. That block has neither a hash nor an accepted header; unsigned height arithmetic instead underflows unless explicitly handled. Core's `SelectQuorumForSigningStartBlock` returns no start block for negative heights (`v24 llmq/quorumsman.cpp:711–721`). The design therefore cannot authenticate the required target or establish the store. Falling back to genesis again cannot create that history, so the MN/wallet subscribers remain unstarted despite header sync being complete. At tips below 8, the other required target is nonexistent too.

Clamping arithmetic alone does not settle the bootstrap rule. With default Core regtest **DIP3 activation at 432** (`v24 chainparams.cpp:818`), tip **450** gives valid endpoint heights **442 and 394**. Height 394 has an ordinary coinbase, without the CbTx roots required by steps 3–4: Core's miner emits the special coinbase payload only when DIP3 is active (`v24 node/miner.cpp:262–279`, `:291–295`). `BuildSimplifiedMNListDiff` returns the actual target coinbase (`evo/smldiff.cpp:235`); it cannot supply nonexistent roots. Requiring that proof at the older endpoint again blocks `Candidate → Established`. These are permitted young-chain states, not missing below-anchor quorum history or an operator-requested resync.

**Suggested fix:** define the recent-lock domain as the available selection-start heights intersected with the horizon. Clip at **genesis**, and explicitly handle an empty domain when no valid sign/selection height exists. For targets before the relevant MN/quorum commitment rules activate, specify the canonical empty/not-yet-active state using the shared deployment rules, rather than requiring a CbTx/root that does not exist. Preserve authenticated steps 1–5 wherever those commitments can exist, and preserve fallback when a real required target/history lies below a non-genesis anchor. Genesis with no usable quorums must be able to establish and start ordinary wallet/header subscribers; lock verification can remain unavailable until quorums exist.

Add SB11/SB15 bootstrap gates at genesis, just below/at sign offset 8, just below/at `H_keep`, and across the CbTx/quorum activation boundary. Include **tip 20** and **tip 450** controls with the default regtest activation settings. Check that no negative/nonexistent target is requested, establishment completes when no actual required history is missing, and later commitment arrival uses the normal authenticated pipeline. This needs no runtime re-anchor and no change to DEC-107's later-miss policy.
