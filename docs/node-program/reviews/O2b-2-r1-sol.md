# O2b-2 ChainSession — Sol review, round 1

**Verdict: CHANGES REQUIRED.** I reviewed `a5d2a9c59..9c1e2c7bf` on a detached worktree against the pinned Core ABI 22 (`5c9e9117a2`). The binding's lock, FFI lifetime, report buffer retry, poison, hash byte order and StateDigest memory-header paths look sound. The restore test does not yet establish that `restore` uses its image.

## Findings

1. **Major — the restore test passes when `restore` ignores the saved image.** `dash-oracle-sys/tests/chain_session.rs:427-445`; binding at `dash-oracle-sys/src/chain.rs:391-403`; Core's image replacement at `src/test/oracle/oracle_chain.cpp:1310-1326`. I replaced the binding's `chain_restore(image, ...)` call with `chain_step(RESTART KILL, ...)`, which reloads current storage and never reads `image`. All 10 `chain_session` tests passed, including `a_restored_image_replays_the_suffix_identically`. The current suffix leaves storage equivalent to the saved image by the time it calls `restore`; checking only `persisted`, success and replay cannot distinguish those implementations. **Fix:** make current storage durably different before restoring, assert the restored post-state equals the saved state and excludes that difference, then replay the suffix. A trial that does a CLEAN restart after the suffix's `SPORK_OFF` and asserts spork 19 is on immediately after restore passed with real `chain_restore` and failed the no-image mutant. **Schedule:** O2b-2, before merge; this is the required restore proof for O2b-3.

2. **Minor — `save()` discards the reload refusal reason.** `dash-oracle-sys/src/chain.rs:365-379`; Core `src/test/oracle/oracle_chain.cpp:1292-1306`. Core sets `oracle_last_error` to `load_message` when the reload is refused. The binding turns `ORACLE_REJECT` plus an image into `SaveOutcome::ReloadRefused(CoreImage)` without reading that message; later operations only report `session-down`. The tested future-tip refusal is therefore diagnosable through `chain_session`'s `Refused(String)` path but not through `save()`. Carry the message in `ReloadRefused` and capture it before another FFI call. **Schedule:** O2b-2, before O2b-3 consumes the API.
