### 2. Minor — an optional masternode member hit contradicts the exact event-trace gate

**Counterexample:** a cold size-1 quorum on a masternode with no stored contributions produces one MEMBERS request with `populate_cache=true`, but two with `false`. The second is a base-cache hit. If Rust takes the permitted omission, its trace lacks Core's `MEMBERS(outcome=base-hit)` event despite equal members and rows. The extracted materializer harness reproduces the one-versus-two requests at both pins. The current non-masternode oracle configuration does not expose this case.

**Fix:** retain the second access when the masternode contribution path reaches it, remove the permission to omit it, and qualify line 795 to the initial build access and row writes. If QM1a's masternode suite compares Core event traces, give its oracle the matching DKG configuration; otherwise explicitly keep this suite non-masternode and test the DKG access stream separately.
