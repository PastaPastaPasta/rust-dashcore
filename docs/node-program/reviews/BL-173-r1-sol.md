# BL-173 review — Sol r1

**Verdict: CHANGES REQUIRED**

## Findings

1. **High — A real empty-input timeout can be discarded when workers share an artifact name.** `node-fuzz/fuzzctl.py:459-485` unions artifact *basenames* from all worker logs, then excludes an empty `timeout-*` file if any worker wrote that basename after `run interrupted`; `node-fuzz/fuzzctl.py:488-493` removes it from all finding paths. libFuzzer names timeout artifacts by a hash of the input (`libfuzzer/FuzzerLoop.cpp:644-652` in the locked libfuzzer-sys source), so every empty input has the same name. With `-jobs`, one worker can genuinely time out on the empty input before any interrupt while another later prints `run interrupted` and writes its empty timeout under the same name; libFuzzer continues its other jobs after one exits (`libfuzzer/FuzzerDriver.cpp:231-252`). I reproduced the two-log fixture: `phantom_timeouts` returned the shared name, `crash_files` returned `[]`, and `run_findings()['crashes']` was 0. This violates D6 and can silently lose a real finding and let a leg keep credit or certify eligibility it should lose. **Fix:** do not infer that a run-wide file is a phantom from a later same-name log entry. Preserve the finding when any worker logged that artifact before an interrupt, and add a two-worker, same-name regression test. For ambiguous provenance, keep the finding or independently replay it before suppressing it.

2. **Medium — Existing phantom `finding` ledger rows still void credit after the new triage rule.** `node-fuzz/fuzzctl.py:1193-1204` resets a leg's credit on every recorded `finding`; `node-fuzz/fuzzctl.py:2122-2129` only reaccounts starts without a done row, and `node-fuzz/fuzzctl.py:757-768` skips runs already in triage state. A phantom recorded by the old code as a completed `finding` remains so after this update, even if recheck closes its cluster or the run's artifact is now recognized as a harness event. A resumed night therefore reports its prior clean CPU as uncredited and schedules the leg's share again. **Fix:** provide an auditable correction for previously completed rows proved to contain only a phantom, or explicitly scope the fix to new/unaccounted slices and document that older nights need repair. Add a resumed-night regression test.

3. **Medium — A phantom outside a farm-issued stop can still retire a running leg after two occurrences.** For a manual SIGINT of a farm slice, D4 recognizes the empty artifact and `node-fuzz/fuzzctl.py:2101-2105` subtracts it from crash counts. But without `result.interrupted`, a stop file, or exit 72, `node-fuzz/fuzzctl.py:2107-2114` returns `fail` for libFuzzer's timeout exit; `node-fuzz/fuzzctl.py:2304-2307` retires the leg on its second such failure, and `credit_by_leg` gives those slices no credit. The notes explicitly include manual SIGINT in the safety net. **Fix:** once phantom classification is safe, treat a run whose only failure evidence is a verified interrupted timeout as `interrupted`, including when the farm did not write the stop file. Test the live-slice ledger, credit, and two-failure retirement path.

## Checks and limits

- `python3 -I node-fuzz/fuzzctl.py selftest` passed: **165 tests, 5 skipped**. The skipped tests require a built real libFuzzer binary; no build was run, as requested.
- The new `InterruptedSlices` cases depend on helpers and accounting absent from the base revision, and the `RunShStopFile` cases require the new `-stop_file` argument and segment-loop check. They would fail on the old code. They pin the ordinary farm stop, pre-INITED SIGINT, fallback SIGKILL, phantom filtering, and single-worker real-timeout boundary. The fake slice places its timeout artifact before the stop, so it does not exercise the actual alarm/grace ordering or the multi-worker collision in finding 1.
- `run.sh:624-650` checks the stop file before each segment; a file written just after the check may allow one more segment to start, but that segment receives the same `-stop_file` and the farm's fallback remains armed. The 90 s + 30 s waits plus the 0.5 s poll fit within `imminent=180` and `TimeoutStopSec=180` in the normal path. They do **not** guarantee SIGKILL before libFuzzer's ALARM, because the 1200 s timeout may already be nearly spent when the stop is requested; the artifact classification remains necessary. The process-group fallback covers a worker that does not reach INITED, and I found no definite normal-path orphan from the reviewed code.
- The documented lost `/usr/bin/time` CPU record on SIGKILL is bounded to a killed segment, and certify's wall-cap ALARM still fails its verdict via the saved crash count (`node-fuzz/run.sh:787-850`, `node-fuzz/fuzzctl.py:1563-1582`). Those recorded gaps are acceptable for this slice.

**Verdict summary:** CHANGES REQUIRED. The stop-file and escalation path addresses the common phantom timeout, and the selftest passes, but run-wide basename matching can erase a genuine empty-input timeout. Existing completed ledger rows can still void credit, and phantoms from manual interruption can still retire a leg. Resolve the classification and accounting gaps before accepting the change.
