**New finding — major: checkpoint may certify unwritten batched data.** `designs/ST3a-power-loss.md:851,852,870` (also `:754`). The toy writes at most two Buffered data batches per flush interval: halfway and at the commit step. The final commit explicitly writes its last data batch before sync_wal; the new checkpoint only specifies sync_wal and a Durable locator commit. In S11d with L=0, p=96, new=98, the first batch can cover through49 while50–96 remain staged. The checkpoint returns with durable locator96 but data only through49. A crash before resume preserves locator96; blind deletion of97–192 cannot recreate50–96, violating R11c(i). A crash before checkpoint return may also retain its atomic locator batch after the preceding barrier, producing the same image. **Fix:** submit all staged subscriber data through p before the checkpoint's sync_wal starts (or include it with the locator atomically while preserving the pre-locator scope requirement), update the batching/budget rules, and test crashes before and after return with outstanding staged data. Treat the processed tip and submitted-data tip separately in the regression.
