## Round-2 findings

1. **CLOSED — passphrase file owner-only.** `.github/workflows/tauri-selftest.yml:142-150` sets `umask 077` before creation, sets mode 0600 on Unix, and applies an owner ACL on Windows before writing the secret. `dw_fs::open_owner_only` (`rust/crates/dw-fs/src/lib.rs:135-175`) opens with `O_NOFOLLOW|O_NONBLOCK`, then checks the opened descriptor is a regular file owned by the effective uid with no group/other bits. `selftest_unlock` uses it and maps refusal to `app.selftest_passphrase_file` (`rust/crates/dw-app/src/api/selftest.rs:116-132`); the judge test prints the code. The real `dw-fs` test passed. A scratch mutation changing the mask to allow 0640 made `an_owner_only_file_has_no_group_or_other_access` fail at its 0640 case. Windows omission is D16's explicit accepted exception. A parent-symlink limit is noted below.

2. **OPEN — relocated fixture copy guard.** Baseline `pnpm build` reported none of 77 sentinels in `dist/`; `pnpm build:fixture` found all 77; `guard-negative-control.sh` refused an unmarked relocated `wallet.ts` copy with 20 sentinels. The fixed 28-item `SHARED` list is checked against actual overlap, and `GENERIC` entries must still be fixture literals. However, the guard omits `.mts` sources and the tests omit `.mts` modules. In scratch, I added a marked `src/fixture/review-extra.mts` with a distinctive literal, copied it without the marker to `src/guard-copy/review-extra.mts`, and dynamically imported the copy. `pnpm build` passed, focused fixture/sentinel tests passed, and the literal appeared in `dist/assets/review-extra-*.js` while the checker still reported 77 clean sentinels. See major finding 1. Dropping `scenarios.ts` from sentinel source collection likewise left the focused tests and fixture positive check green (77 became 75), showing the source list is not fully pinned by the current tests. The exemption lists can also hide a copy if edited: an unmarked `errors.ts` copy raised overlap by seven entries; adding them to `SHARED` made the tests and production build pass with `Block height out of range` in `dist/`. That edit is visible for review, but the equality test does not forbid it. See major finding 2.

3. **CLOSED — release binary selftest gating.** `dw-app` has an off-by-default `selftest` feature. The macro in `rust/crates/dw-app/src/ipc.rs` gates all five command functions and their dispatcher, while keeping specs for code generation. The CLI arms in `launch.rs:141-154` and runtime capability grant in `lib.rs:167-169` are gated; the selftest capability sits outside `capabilities/`, and `api::tests::the_embedded_capabilities_grant_no_selftest_command` reads tauri-build's embedded capabilities. The selftest workflow explicitly builds `--features selftest`. The default-build option and IPC tests assert unknown options and “not found.” A scratch mutant ungating the `--selftest` CLI arm made the default option test fail. The default `dw-app` tests passed: the three CLI flags are unknown and all five IPC names return “not found.” The compiled default binary exited 2 with `dash-wallet: unknown option --selftest` when given `--selftest`. The default embedded-capability test passed. The feature-on `dw-app` library suite passed all 124 tests, including successful selftest IPC, passphrase-file refusal, capability parsing, and `codegen::tests::bindings_are_current`. The same bindings test passed under the default feature set, proving generated TS is identical in both configurations.

## New findings

1. **Major — `apps/desktop/scripts/fixture-sentinels.mjs:89`, `apps/desktop/src/fixture/fixture.test.ts:37`.** Both source discovery and the fixture module assertion accept only `.ts`/`.tsx`. A new fixture `.mts` module is therefore neither checked for the marker nor used as a sentinel source. Its unmarked relocated copy can be emitted into a production JS chunk with a distinctive fixture literal while `pnpm build` and tests pass. Repro above. Include every Vite-loadable source extension used in the renderer (at least `.mts`), and add a negative control that proves each fixture module contributes a checked literal or fails explicitly when it cannot.

2. **Major — `apps/desktop/scripts/fixture-sentinels.mjs:35-75`, `apps/desktop/src/fixture/sentinels.test.ts:12-22`.** The `SHARED` equality test accepts a newly relocated fixture copy as the reason for new overlap. In scratch, copying `errors.ts` outside `src/fixture/` made the test fail; adding seven overlapping literals to `SHARED` made the test and production build pass even though a fixture error literal was emitted in `dist/`. An entry in `GENERIC` can also exempt any current fixture literal without a rationale check. The lists are reviewable but are not a mechanical barrier to hiding a copy. Keep a fixed approved overlap baseline independent of current nonfixture source, or fail when new overlap is caused by emitted production code; require a separate narrow justification for exemption changes.

3. **Minor — `rust/crates/dw-fs/src/lib.rs:143`.** `O_NOFOLLOW` applies only to the last path component. A scratch test showed `open_owner_only(alias/passphrase)` succeeds when `alias` is a symlink to a directory containing an owner-only 0600 file. The final descriptor's uid and mode checks still protect against another user reading that file, so this is a path-policy gap rather than a demonstrated passphrase leak. If “no symlink in the path” is intended, open each parent with `openat`/`O_NOFOLLOW` and test it; otherwise narrow the D16 wording to “final component.”
