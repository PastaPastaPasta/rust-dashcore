# BL-173 narrow review — Sol r5 (D15/D16)

**Verdict: CHANGES-REQUIRED**

## Findings

1. **Major — The `-jobs` inventory can look complete after its last real worker disappears from both records.** `node-fuzz/fuzzctl.py:505-516,544-559`; `node-fuzz/run.sh:603,647`. The run knows `--jobs J`, but `logs_complete` reconstructs the expected workers solely from the surviving `fuzz-<i>.log` files and `Job <i> exited` lines. I made two workers write the same empty `timeout-0123`: worker 0 after `run interrupted`, worker 1 before any interrupt. After removing `fuzz-1.log` and cutting `fuzz.out` just before worker 1's exit line and copy, `logs_complete` returned `True`, `phantom_timeouts` returned `['timeout-0123']`, `run_findings()['crashes']` became 0, and `findings_of` became empty. One full-disk or truncated-run episode can leave both the worker log and the parent's later copy/exit line absent; the empty artifact from worker 0 remains. The code cannot prove the full worker inventory from the surviving records, and every consumer of `phantom_timeouts` inherits the false classification. **Fix:** persist the intended worker count independently when the segment starts, and require all expected numbered worker logs and parent exits before classifying any phantom. Runs without this independent count need a conservative rule.

2. **Major — A cut lone-process merge log can turn a later real same-name timeout into a phantom.** `node-fuzz/fuzzctl.py:505-526,544-559,1204-1217`. I made a `fuzz.out` with `MERGE-OUTER: attempt 1`, an interrupted empty `timeout-0123` write, then `MERGE-OUTER: attempt 2` and a real write of the same name before an interrupt. With the full log, `phantom_timeouts` was empty and `run_findings()['crashes']` was 1. Cutting that one log before attempt 2, while retaining the saved artifact, left the sole `fuzz.out` present, so `logs_complete` still returned `True`; `phantom_timeouts` returned the name, `run_findings()['crashes']` fell to 0, and `findings_of` was empty. A recorded `hit_sources=[{run: r1, log: segment-1/fuzz.out}]` then made `verified_hit()['phantom']` true and `phantom_verdict` return no reason to keep the cluster. This is one log truncation, not a missing file; the surviving earlier write is insufficient proof about later merge attempts. **Fix:** fail closed for merge logs without independently verified completion of their attempts, or exclude merge logs from phantom classification. The per-hit check must consume that stronger proof too.
