Target: `node/bs11a-design` at `bb32551eb`; delta `5c52de0e1..bb32551eb`. I reviewed the design against the BS12 v24.0 oracle pin (`0dd12af0644b5b3aafc8d60cb2a786292d7788b0`) and the supplied rebuilt objects. No repository files were modified.

## Finding

### Minor — the cache model should use Core's null sentinel, not an independent populated flag

F10 and the `SER` row say a first `GetHash()` populates the cache and every later call avoids relic; §7 says `SER` sets a per-register cache flag. Core actually tests `cachedHash.IsNull()` on **every** call (`src/bls/bls.h:141-146`). If `SerializeHash(*this)` yields the all-zero `uint256`, the stored value is still null and the next `SER` serializes again. Thus the exact transition is “cache value is null → serialize and store the digest,” not “first call → populated flag.” This is a rare digest condition, with no known reachable vector, so it does not undermine the ordinary uncached/cached scripts or the rev6 repair. State the sentinel rule in F10, the `SER` row and the model; a separate flag may be used only if it is derived from `!cachedHash.IsNull()` after the assignment.
