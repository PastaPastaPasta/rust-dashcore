# O2b `diff_chain` rev3 — narrow Sol r3 review

**Verdict: CHANGES REQUIRED.** The five r2 design changes are present, and the signed `UpdateSpork` route is sound. The new spork experiment needs two corrections before it can gate M3.

## Findings

1. **MAJOR — §8, D34: the X-check calls the read-only spork RPC for an update.** §8 says `SPORK` maps to `dashd`'s `spork` RPC and gives `spork SPORK_19_CHAINLOCKS_ENABLED 0` as the experiment. In Core v24, `spork` accepts only `show` or `active` (`src/rpc/node.cpp:156-202`); `sporkupdate` accepts the name and value and calls `UpdateSpork` (`src/rpc/node.cpp:207-245`). As written, the gate cannot execute its update. **Fix:** use `sporkupdate SPORK_19_CHAINLOCKS_ENABLED <value>` in both §8 bullets and in the X-check mapping; retain `spork show` for observation.

2. **MAJOR — §§2.3, 8, D34: make the persistence experiment distinguish `KILL` from `CLEAN`.** Rev3 saves every M3 prefix with spork 19 already at `0` (on), but §8 updates it to `0` again before the two restarts. If the experiment uses that prefix, a killed restart and a clean restart both read `0`, even if the killed session incorrectly stores the new spork. This would admit spork intents without proving the chosen persistence model. Core's default is `4070908800` (off; `src/spork.h:69`), and activation is `value < adjusted time` (`src/spork.cpp:163-169`); the manager stores on destruction and loads at startup (`src/spork.cpp:46-59`, `src/init.cpp:1967-1972`). **Fix:** start each trial from the same clean-saved baseline with spork 19 on, update it to `4070908800` (off), assert off before restart, then assert on after `KILL` and off after `CLEAN` on `dashd`, the session, and `NodeSut`. Alternatively specify a fresh off baseline and update it to on for all three. Keep the trials isolated so a previous clean store cannot mask the killed result.

3. **MINOR — §14 PLAN SP0 and R17: the referenced SP0 commit already has a production shutdown store call.** At `6ce75bf1e`, `dashd-node/src/node.rs:450-454` calls `sporks.store(...)` in shutdown, and `dashd-masternode/src/sporks/file.rs:217,235` defines it as `SporkManager::store`. The text says it has no production caller and that the remaining work is to add one. Core's corresponding call is the manager destructor at `src/init.cpp:415` and `src/spork.cpp:46-50`. **Fix:** describe the M3 work as carrying the existing call into the SP0-s split and testing clean versus killed restart, rather than adding a second call; update R17 accordingly.

4. **NIT — §§0, 6.5, 13: old wording contradicts rev3.** §0 says the session has “no signer,” although §2.1/§2.6 now install a spork signing key (Core `src/spork.cpp:138-160`). §6.5 still calls a mid-op flush “unmirrored,” and R15 says mid-op flushes are “reconciled rather than mirrored,” while D31 now mirrors each flush before reconcile. R16 says “`KILL`-only” suppression although restore teardown suppresses the store too. **Fix:** qualify §0 as no LLMQ signer, call the mid-op mirror *delayed*, and update R15/R16 to match §§2.3 and 2.9.

## R2 resolution checks

- **1, M3 ChainLocks:** resolved in the design. SP0-s is an O2b-3 dependency, M3 images carry spork 19 on, and the Rust op uses production `update_spork`. Core's default is off (`src/spork.h:69`); `HasChainLock`/`HasConflictingChainLock` gate on it (`src/chainlock/chainlock.cpp:33,49-54,73-79`), and the handler's off-to-on reset and enforcement gate are at `src/chainlock/handler.cpp:209-221,273-277`.
- **2, spork persistence:** the specified clean-only store and `KILL`/restore suppression now give matching post-restart state; `sporks` is compared. Core sets `-sporkaddr`/`-sporkkey` before load (`src/init.cpp:1742-1757,1967-1972`), and load-time `CheckAndRemove` keeps messages signed by that key (`src/spork.cpp:52-80`). The experiment needs findings 1–2.
- **3, CLEAN flush:** `flush_delta` now spans teardown and reopen, including the old instance's shutdown flush. Core's `ForceFlushStateToDisk` invokes `ALWAYS` (`src/validation.cpp:3122-3127`).
- **4, mid-op mirrors:** §2.3/D31 now mirror every Rust flush under its cause in order, then reconcile once on each side; the O2b-1/O2b-3 assertions are specified. Core's index write precedes its full coins/evo flush (`src/validation.cpp:3045-3075,3075-3100`).
- **5, CH2-KP and W-P3a:** the durable-phase oracle includes split-flush markers, coin batches, final batch, and index-only writes; it compares recovered coins/evo and index images. W-P3a now uses a mature unspent coin, allowing the intended `SequenceLocks` failure in `ConnectBlock` (`src/validation.cpp:2722-2733`) after the contextual finality check (`src/validation.cpp:4553-4559`).

**Signed spork route:** `UpdateSpork` signs and verifies with the configured key, updates the active map, and only constructs a `CInv` (`src/spork.cpp:138-160`). The RPC's subsequent `EnsurePeerman`/`RelayInv` is separate (`src/rpc/node.cpp:238-242`), so the session needs no network object. Regtest `-sporkaddr` is used by init (`src/init.cpp:1746-1755`), and the key is set before `LoadCache` (`src/init.cpp:1967-1972`).
