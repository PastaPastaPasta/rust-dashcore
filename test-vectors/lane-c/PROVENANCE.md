## Schema 2 and evidence semantics

Hashes are RPC display order (`GetHex`); payload fields are exact stored wire bytes. The BLS
scheme is basic. `quorum_info.variants` deduplicates public RPC objects; each node selects a
variant and optionally adds its `secretKeyShare` for the true include-secret flag. Both flag
answers are reconstructible. `commitment_hex` excludes the type-6 payload's version/height
header. Native contribution payloads are keyed by member. `signing_quorums` adds contexts for
default-selection quorums outside the explicitly recorded list.
Core's `getrecsig.hash` hashes the BLS signature bytes alone (`src/llmq/core_write.cpp:103-113`);
`requests[].recsig_hash` hashes the full recovered-signature wire object for inventory matching.

`control_phases` names each controlled phase and its held mocktime. Every node's `events`
has a matching `barrier` with convergence `polls`. Polls are barrier inputs, never differential
observations. Ordinary exact RPC observations occur after a barrier with inputs still fixed.
The first threshold submits for an id with no recsig at phase start are marked
`threshold_submit`; a later same-id Platform request has no exact submit booleans. The two
vote-only calls are isolated signs after a barrier. Other sign results are barrier inputs.
There is no settled/racy classification. The final chain-only phase expects no new signatures.

Native write, intake and recovery lines are provenance only. They retain byte positions and
per-node order, and are assigned to controlled phases from their log intervals. Positive RPC
confirmation establishes write completion; a post-delete cleanup line establishes deletion.
Expiry starts at the write phase's held mocktime, rather than its pre-write log line.
Every node has exactly one native write per signHash, no conflicting recoveredSig, and all
remote writes have prior intake plus exact peer/payload evidence. Local writes have a native
recovery line. Recorded writes: {'remote': 493, 'local': 167}.

Signature messages retain their binary-stream `order`, native `receive_pos`, peer id, sender
and receiver node indexes, mocktime and payload. Native receive-log order disambiguates
reconnects to one address; peer addresses and identities come from `getpeerinfo`. The trim
orders records within each receiving node by its log position. It claims no cross-node order
or send-pass boundaries. Message counts: {'qbsigs': 803, 'qgetsigs': 17, 'qsigrec': 1123, 'qsigsesann': 804, 'qsigshare': 132, 'qsigsinv': 309}.

The trim removes duplicated public info and per-node recovered-signature RPC objects, drops
DKG wall-clock time fields, and moves raw blocks into the separate chain file. It checks the
schema, phase barriers, exact-sign roles, unique writes, recovered-signature hashes and
quorum-info reconstruction before writing compact sorted JSON.
The JSON is 5,747,660 bytes (5.48 MiB): event provenance/barrier polls dominate at about
2.22 MB, signature messages at 1.29 MB, and exact observations at 1.14 MB; quorum contributions and
commitment transactions account for the remaining increase. These retain the
required replay evidence. Gitleaks findings match disposable captured keys/shares only;
72 exact generic-api-key value fingerprints are added to `contrib/node/fork-push-secrets.txt`.
